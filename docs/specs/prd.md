## 1. 한 줄 정의

**외국인 K팝 팬이 "최애 + 여행 날짜 + 도시"를 넣으면, 그 날짜에만 열리는 생일카페·팝업과 상설 덕질 장소를 엮어 실제로 갈 수 있는 일정을 만들어 주는 AI 덕질 여행 플래너.**

## 2. 문제

외국인 팬은 가고 싶은 곳을 알아도 **자기 여행 날짜 안에서 실행 가능한 일정**으로 만들지 못한다. (기획안 §2)

| 문제 | 지금 팬이 하는 일 |
|------|-------------------|
| 생일카페·팝업 정보가 한국어·포스터 이미지·팬덤 은어로 흩어져 있다 | X 계정과 한국어 앱을 번역기로 뒤진다 |
| 3~5일짜리 이벤트와 상설 장소가 겹쳐 무엇을 포기할지 모른다 | 달력에 손으로 적어 본다 |
| 특전 조건("선착 100명 럭드")이 무슨 뜻인지 모른다 | 팬 커뮤니티에 물어본다 |

## 3. 목표와 비목표

### 목표 (해커톤 MVP)

| # | 목표 | 확인 방법 |
|---|------|-----------|
| G1 | 심사자가 **가입·설치·키 없이** 3분 안에 입력 → 테마 → Best 3 → 일정까지 끝낸다 | 시크릿 창 수동 시연, `pnpm check:prod` |
| G2 | 생성된 일정에 **운영 기간·영업시간 위반이 0건**이다 | 규칙 검증 테스트 |
| G3 | 일정이 겹치면 **이유와 선택지**를 보여준다 | 충돌 시나리오 테스트 |
| G4 | 이벤트 정보가 **원출처(주최자 X 공지)에 연결**되고 특전이 행동 단위로 설명된다 | 장소 카드 검수 |
| G5 | 브랜드 가이드 톤으로 **3개 뷰포트에서 깨짐 없이** 보인다 | `pnpm capture` 캡처 |

### 비목표 (이번에 하지 않음)

회원가입·로그인, 실제 결제·가이드 매칭, 실시간 위치 추적, 영어 외 언어, 아그리게이터 데이터 수집, 체크인·포인트·커뮤니티 실제 동작(목업만), B2B 데이터 판매 기능. (기획안 §7.3)

## 7. 핵심 요구사항 요약

상세 조건·예외·수용 기준은 [기능명세서](functional-spec.md).

1. **날짜가 먼저다.** 여행 날짜 없이는 다음 단계로 못 간다. 후보는 여행 기간과 운영 기간이 겹치는 곳만.
2. **틀리면 안 되는 계산은 규칙으로.** 기간 겹침, 영업시간, 충돌, 이동 거리, 테마 점수는 코드가 계산한다. AI는 동선 순서와 설명 문장만.
3. **AI가 실패해도 일정은 나온다.** 시간 초과·오류·검증 실패 시 규칙 기반 기본 일정을 보여주고 사용자에게는 차이를 드러내지 않는다 (로그로만 구분).
4. **원출처 연결.** 모든 기간 한정 이벤트는 원 게시물 링크를 가진다. 원문이 삭제되면 노출하지 않는다.
5. **샘플은 샘플이라고 말한다.** 데모용 날짜로 만든 이벤트는 "Sample event" 배지.
6. **사생활.** 사옥·숙소·자택 등 개인·업무 공간은 데이터에 넣지 않는다.
7. **키는 서버에만.** OpenAI·X·Supabase 서비스 키·TourAPI 키는 브라우저로 나가지 않는다.
