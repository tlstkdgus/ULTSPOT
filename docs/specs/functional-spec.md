## 3. 기능 상세

각 기능은 **목적 → 입력 → 처리 → 출력 → 예외 → 수용 기준** 순서.

### F-01 랜딩·시작 · P0 · S-01

**목적** 심사자와 팬이 이 서비스가 무엇인지 5초 안에 알고, 바로 시작한다.

| 요소 | 내용 |
|------|------|
| 헤드라인 | `FIND YOUR SPOT.` (현재 임시 랜딩 유지) + 부제 `Your bias's birthday cafes, pop-ups and filming spots — planned around your travel dates.` |
| CTA 1 (primary) | `Plan my trip` → S-02 |
| CTA 2 (ghost) | `Try the demo trip` → 데모 값을 채워 S-05로 바로 이동 [제안] |
| 보조 | 3단계 설명(Dates → Theme → Itinerary), 도트 필드 배경 |

**데모 여행 값** [제안] — 샘플 이벤트 기간과 겹치게 고정한다 (§5 D-06과 함께 확정)

| 항목 | 값 |
|------|----|
| 날짜 | D-06에서 정한 샘플 기간 안의 3일 |
| 도시 · 최애 | Seoul · Stray Kids · Felix |
| 테마 답 | `A A B A A` → Cup Sleeve Collector, 하루 4곳, 대기 high |
| Best 3 | 정렬 1~3위 자동 선택 (사용자가 바꿀 수 있음) |

**수용 기준**
- [ ] 시크릿 창·390px 폭에서 CTA 2개가 첫 화면 안에 보인다
- [ ] `Try the demo trip` 에서 일정 화면까지 **입력 없이 탭 2번**(Best 3 확인 → Generate)으로 도달한다

### F-02 기본 입력 · P0 · S-02

**목적** 날짜를 가장 먼저 받는다 (기획안 §2.2 "날짜가 먼저").

**입력**

| 필드 | UI | 규칙 | 오류 문구 |
|------|----|------|-----------|
| 여행 기간 | 날짜 범위 선택 (DateChip 연속 선택) | 필수. 시작 ≤ 종료. **1~7일** [제안] | `Pick your arrival and departure dates.` / `Trips up to 7 days for now.` |
| 도시 | 선택 | `Seoul` 만 활성. 다른 도시는 비활성 칩 `Coming soon` | — |
| 그룹 | 선택 | `Stray Kids` 만 활성 (데모 데이터 범위) | — |
| 최애 | 단일 선택 | 멤버 8명 중 1명 **또는** `Whole group (OT8)` [제안]. 필수 | `Who's your bias?` |

**처리**
1. 값 검증 (위 규칙). 날짜 범위는 과거도 허용한다 — 심사자가 임의 날짜로 확인할 수 있어야 한다 [제안]
2. `sessionStorage.ultspot.plan` 에 저장 (C-11)
3. `GET /api/spots/candidates` 로 후보 수를 미리 조회해 버튼 아래 표시: `12 spots open during your trip` (§4.1)

**출력** S-03으로 이동.

**예외**

| 상황 | 동작 |
|------|------|
| 후보 0곳 | 진행은 허용. 안내 `No limited events on these dates — we'll build around permanent spots.` + `Try the demo trip` 링크 |
| 기간 한정 후보 0곳이고 상설도 0곳 | 진행 막음. `We don't have spots for this trip yet.` + 데모 여행 링크 |
| 후보 조회 실패 | 수를 숨기고 진행 허용 (S-05에서 다시 조회) |

**수용 기준**
- [ ] 날짜 없이 `Next` 가 비활성이다
- [ ] 8일 이상 선택이 막힌다
- [ ] 390px에서 날짜 선택이 가로 스크롤 없이 동작한다 (smoke 테스트)

### F-03 덕질여행 테마 테스트 · P0 · S-03, S-04

**목적** 취향을 일정 생성용 숫자로 바꾼다. **상세 규칙의 원문은 [theme-test.md](theme-test.md)** — 이 절은 구현 계약만 적는다.

**입력** 5문항 × 보기 4개. 한 화면에 한 문항, 상단 진행 도트 5개.

**처리** (규칙, AI 없음)

| 출력 | 계산 |
|------|------|
| `theme` | C/S/T/R 점수 최고. 동점 → Q4 테마 → Q1 테마 순. 1·2위 동점이면 `hybrid: [1위, 2위]` |
| `weights` | `(score + 1) / 11` → `birthday_cafe`·`filming_spot`·`bias_eats`·`popup` (합 1.0) |
| `spotsPerDay` | Q3 → 6 / 4 / 3 / 2 |
| `queueTolerance` | Q2 + Q5 대기값 → ≤0 `low` · 1~2 `mid` · ≥3 `high` |

**출력 (S-04)** 테마 이름(`text-display`), 한 줄 설명(고정 문구), 가중치 도트 시각화, 하루 장소 수·대기 성향 요약, CTA `Pick your Best 3`.

**예외**
- 뒤로 가기: 이전 문항으로, 답 유지
- 결과 설명 AI 개인화는 **하지 않는다** (theme-test.md 오픈 이슈, 비용·일관성)

**수용 기준**
- [ ] 단위 테스트: theme-test.md §5 예시 5개가 표와 같은 값
- [ ] 단위 테스트: 1,024개 조합 전수 — 1위 테마 256건씩, 동점 256건
- [ ] 같은 답은 새로고침·다른 기기에서도 같은 결과

### F-04 후보 목록·Best 3 선택 · P0 · S-05

**목적** 여행 기간에 갈 수 있는 곳 중 꼭 갈 3곳을 고르게 한다. 고른 3곳이 충돌 판정의 기준이 된다.

**입력** F-02 값, F-03 결과.

**처리**
1. 후보 = §4.1 필터
2. 정렬 = §4.2 점수 내림차순, 동점이면 종료일 빠른 순 → 이름순
3. 유형 필터 칩 (All / Birthday cafes / Pop-ups / Filming spots / Bias eats), 기본 All

**카드 표시** (Card 컴포넌트)

| 요소 | 규칙 |
|------|------|
| 이름 (EN) · 지역 | 필수 |
| 유형 배지 | 4종 |
| 기간 배지 | 기간 한정만. 여행 기간과 겹치는 날을 `Sep 14 – 16 on your trip` 로. 여행 시작 후 2일 안에 끝나면 `closing` 톤 `Ends Sep 15` [제안] |
| 최애 표시 | 선택 멤버 전용이면 멤버 이름 강조 |
| 대기 표시 | `queue_level = first_come` 이고 대기 허용도 `low` 면 `Long queue likely` 경고 |
| 샘플 배지 | C-7 |
| 선택 | 체크 토글. 선택 순서대로 1·2·3 번호 |

**규칙**
- 최대 3곳. 4번째 선택 시 토스트 `Best 3 only — unpick one first.`
- 최소 1곳 [제안]. 후보가 3곳 미만이면 있는 만큼만 선택 가능
- 선택한 번호(1·2·3)는 충돌 시 **우선순위**로 쓴다 (§4.6)

**예외**

| 상황 | 동작 |
|------|------|
| 후보 0곳 | 빈 상태: `Nothing open on these dates.` + `Change dates` / `Try the demo trip` |
| 조회 실패 | 오류 상태 + `Retry`. 3회 실패 시 데모 여행 링크 노출 |
| sessionStorage에 F-02 값 없음 | S-02로 이동 |

**수용 기준**
- [ ] 후보에 여행 기간과 겹치지 않는 기간 한정 이벤트가 **0건** (단위 테스트)
- [ ] 정렬 점수가 §4.2 식과 일치 (단위 테스트, 고정 데이터 10건)
- [ ] 4번째 선택이 막힌다

### F-05 일정 생성 · P0 · S-06, S-08

**목적** Best 3를 고정하고 나머지를 채워, 날짜별로 실제 갈 수 있는 일정을 만든다.

**입력** `plan` (F-02), `quiz` (F-03), `best3: spotId[]` (F-04, 순서 = 우선순위).

**처리 순서** — 비용이 드는 AI는 규칙으로 가능성을 확인한 뒤에만 부른다

| 단계 | 담당 | 내용 | 실패 시 |
|------|------|------|---------|

|------|------|

| `LATE_ARRIVAL` | 약 | 선착순 이벤트인데 오픈 시각 30분 후 이후 도착 [제안] | S-08 경고 + `Move earlier` 제안 |

**S-07 충돌 시트**

```
Can't fit both on Sep 15
┌──────────────────────────┐  ┌──────────────────────────┐
│ #1 Felix Birthday Cafe   │  │ #3 SKZ Pop-up            │
│ Only Sep 15 · 11–19      │  │ Only Sep 15 · 12–18      │
└──────────────────────────┘  └──────────────────────────┘
Why: Both are only open Sep 15, and the 55 min trip between
them leaves under 1 hour at the second spot.
[ Keep Felix Birthday Cafe ]  [ Keep SKZ Pop-up ]
```

**수용 기준**

## 4. 계산 규칙

모두 순수 함수로 구현하고 단위 테스트로 고정한다. 위치 [제안]: `src/lib/planner/`.

### 4.1 후보 필터

```
입력: tripStart, tripEnd (포함), city, artistId, memberId | null
후보 = spots 중
  status = 'published'
  AND city = 입력 city
  AND artist_id = 입력 artistId
  AND (기간 한정이면 원출처 available = true)
  AND (
        상설(end_date IS NULL)
     OR openDays(spot, tripStart..tripEnd) ≥ 1
  )

openDays(spot, 범위) = 범위 안의 날짜 d 중
  start_date ≤ d ≤ end_date
  AND d의 요일이 closed_days에 없음
  AND hours[d의 요일] 가 있음
```

> 기간 겹침만 보지 않고 **실제로 여는 날**을 센다 — 월요일 휴무 카페가 여행 기간 중 월요일에만 겹치면 후보가 아니다.

### 4.2 Best 3 정렬 점수

theme-test.md §6을 따른다.

```
score = weights[spot.type] × dateFit × biasMatch

dateFit
  상설                     = 0.7
  기간 한정                = min(1.0, openDays(spot, 여행기간) / openDays(spot, 전체 운영기간))

biasMatch  (최애 = 멤버 m 선택 시)
  m 전용 이벤트             = 1.0
  그룹 전체                 = 0.8
  다른 멤버 전용            = 0.3
biasMatch  (최애 = Whole group 선택 시) [제안]
  그룹 전체                 = 1.0
  멤버 전용                 = 0.8
```

### 4.3 이동 시간 [제안]

지도 API 미정이라 좌표만으로 계산한다. 지도 API가 정해지면 이 절만 바꾼다.

```
d = haversine(a, b) km
route = d × 1.3                      (직선 → 실제 경로 보정)
if route ≤ 1.5 km:  minutes = route × 15          (도보 4 km/h)
else:               minutes = 15 + route × 4      (대중교통: 도보·대기·환승 15분 + 15 km/h)
minutes = ceil(minutes / 5) × 5
```

**[결정 2026-09-19]** 기준 거리와 계수는 매니패스트 값을 따른다. 서울 지하철은 역까지 걷기·대기·환승을 합치면 15분은 고정으로 잡아야 실제와 맞고, 값이 클수록 일정이 덜 빡빡해져 헛걸음이 줄어든다.

### 4.4 체류 시간과 도착 시각 [제안]

| 유형 | 기본 체류 | 대기 가산 |
|------|-----------|-----------|
| `birthday_cafe` | 60분 | `queue_level = first_come` 이고 허용도 `high` → +60분, `mid` → +30분, `low` → 0 |
| `popup` | 60분 | 위와 같음 |
| `filming_spot` | 30분 | 0 |
| `bias_eats` | 60분 | 0 |

- 선착순(`first_come`) 이벤트: 허용도 `high`·`mid`면 **오픈 시각에 도착**하도록 그날 첫 방문으로 우선 배치
- 방문 = [도착, 도착 + 체류]. 도착 ≥ 영업 시작, 도착 + 체류 ≤ 영업 종료, 전체가 하루 창(10:00~21:00) 안
- 식사: `bias_eats` 가 12:00~14:00에 걸치면 식사로 간주. 없으면 12:30~13:30을 비워 둔다 (F-11 트리거) [제안]

### 4.5 기본 일정 (AI 없이)

```
1. 날짜별 빈 일정 N일
2. Best 3 배치 (우선순위 1→3):
     그 장소가 여는 날 중 → 이미 배치된 수가 적은 날 → 이른 날
     그날 안에서 §4.4 조건 만족하는 가장 이른 시각
3. 나머지 슬롯 채우기 (날짜 순):
     남은 후보를 score 내림차순으로 보되,
     직전 방문 장소에서 이동 시간 40분 이내인 후보를 먼저 [제안]
     §4.4 조건 만족하면 넣고, 하루 방문 수 = spotsPerDay 가 되면 다음 날
4. 같은 장소는 여행 전체에서 1번만
5. 하루 안 순서: 고정 시각(선착순 오픈 도착)을 먼저 두고, 나머지는 최근접 이웃 순
```

같은 입력이면 항상 같은 결과 (동점 정렬 키: score → end_date → spotId).

### 4.6 충돌 판정

Best 3만 대상으로 §4.5-2 배치 전에 판정한다.

```
DATE_NO_OVERLAP   openDays(spot, 여행기간) = 0
DAY_OVER_CAPACITY 어떤 날 d에 "d에만 열 수 있는" Best 3 수 > spotsPerDay
SAME_SLOT         두 장소 A, B가 여는 날의 교집합만 남고(각자 다른 날 없음),
                  그날 A→B, B→A 두 순서 모두 §4.4 조건을 만족하지 못함
QUEUE_RISK (약)   queue_level = first_come AND queueTolerance = low
LATE_ARRIVAL (약) first_come AND 배치된 도착 > 오픈 + 30분
```

강한 충돌이 여러 개면 우선순위 1번이 관련된 것부터 하나씩 묻는다.

### 4.7 AI 결과 검증

AI 응답(JSON)은 아래를 **모두** 통과해야 쓴다. 하나라도 실패하면 기본 일정.

| # | 검사 |
|---|------|
| V-1 | JSON 스키마 일치 (zod 등) |
| V-2 | 모든 `spotId` 가 요청한 후보 풀 안에 있고 중복 없음 |
| V-3 | 강한 충돌 해결 후 남은 Best 3가 모두 포함 |
| V-4 | 각 방문이 §4.4 조건(운영 기간·요일·영업시간·하루 창) 만족 |
| V-5 | 같은 날 방문이 겹치지 않고 간격 ≥ §4.3 이동 시간 |
| V-6 | 하루 방문 수 ≤ `spotsPerDay` |
| V-7 | 설명 문장 길이 ≤ 160자, 장소 이름 외 고유명사(가게·주소) 새로 만들지 않음 — 후보 이름 목록에 없는 대문자 고유명사가 있으면 **문장만** 고정 문구로 교체 [제안] |

시각은 AI가 준 값을 쓰지 않고 **AI가 정한 순서·날짜로 규칙이 다시 계산**한다 [제안] — AI의 시간 계산 오류를 원천 차단.

| 충돌 | 데모 여행 날짜에서 강한 충돌이 **1건** 나도록 기간·영업시간을 맞춘다 — 충돌 판정이 핵심 기능인데 충돌이 없으면 심사자가 볼 수 없다 |

| 응답 | `200 { itinerary, warnings }` |
| OpenAI | 서버 전용 키. **타임아웃 15초** [제안]. 모델은 구현 시 결정 (구조화 출력 지원 모델). 입력: 후보 풀(id·유형·좌표·운영 조건·점수)과 기본 일정. 출력: 날짜별 `spotId` 순서 + 하루 설명 |
| 호출 제한 | IP당 분당 5회 [제안]. 초과 시 AI 건너뛰고 기본 일정 (429를 사용자에게 보이지 않음) |
| 비용 제한 | OpenAI 대시보드 월 한도 설정 (사용자 작업) |
| 로그 | `generator`, `fallback_reason`, 소요 ms. 입력·출력 본문은 로그에 남기지 않음 |

### 7.4 세부 조정 — 서버 호출 없음

**[결정 2026-09-19]** 조정은 클라이언트에서 §4.3~§4.5 규칙으로 다시 계산하고 `localStorage`에 덮어쓴다. 서버 재검증(`PATCH`)은 저장이 서버에 없으므로 필요 없다. 계산 코드는 서버와 같은 모듈(`src/lib/planner/`)을 쓴다.
