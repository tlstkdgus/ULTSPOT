# 지도·경로 연동 검토 (T-019)

2026-09-20 조사. ULTSPOT은 생일카페 같은 팬 행사를 중심으로 실제 하루 동선을 짜는 여행 플래너다. 이동시간이 틀리면 일정 자체가 쓸 수 없다. 이 문서는 현재 한계, API 후보 비교, 선택, 키 없이 만들 수 있는 범위를 나눈다.

아래 요금·제한 중 **카카오맵 항목만 원문 공지에서 직접 확인했다.** 나머지는 공식 문서 주소만 확인했고 금액·무료량은 신청 화면에서 다시 봐야 한다. 확인하지 않은 숫자는 적지 않았다.

## 1. 현재 한계

`src/lib/trip/planner.ts`와 `src/components/spot-card.tsx`의 현재 동작:

| 항목 | 현재 | 문제 |
|---|---|---|
| 이동시간 | `input.transfer` 하나(15~120분)를 **모든 구간에 동일**하게 적용 | 종각역→압구정로는 40분, 같은 명동 안 이동은 8분인데 둘 다 45분으로 계산된다. 방문 수가 실제보다 적게 나오거나, 짧게 잡으면 못 지키는 일정이 나온다 |
| 구간 방향 | `travel = previous ? input.transfer : 0`. 첫 장소까지의 이동은 **0분** | 숙소·공항에서 첫 장소까지 가는 시간이 일정에 없다. 11:00 출발이면 11:00에 이미 첫 장소에 있는 것으로 계산된다 |
| 종료 위치 | 없음 | 마지막 장소에서 숙소로 돌아가는 시간이 없다. `input.end`까지 꽉 채운 일정이 실제로는 초과한다 |
| 이동수단 | 없음 | 도보 10분과 지하철 10분을 구분하지 못한다 |
| 좌표 | 없음. `address` 문자열만 | 거리 계산도, 주변 검색도, 경로 조회도 불가능하다 |
| 지도 | `map.naver.com/p/search/{주소}`, `map.kakao.com/link/search/{주소}`, Google Maps 검색 링크 | 표시가 아니라 외부 검색이다. 동선을 볼 수 없다 |
| 운영 예외 | `closedDays`(요일)만 | 공휴일 휴관, 특정 날짜 단축 운영을 표현할 수 없다 |

문서상으로는 "계획용 여유 시간이지 실시간 길찾기가 아니다"라고 밝히고 있다(`t.footer`, `t.day.bufferSummary`). 거짓말은 아니지만, 여행 플래너로서는 부족하다.

## 2. 기능을 3가지로 나눈다

섞으면 비용·약관 판단이 엉킨다.

1. **지도 표시** — 지도 타일/마커를 화면에 그린다. 브라우저 SDK(키가 도메인에 묶여 노출) 또는 서버가 받아오는 정적 지도 이미지.
2. **주소·장소 검색(지오코딩)** — 주소 문자열 → 좌표, 키워드/카테고리 → 주변 장소 목록.
3. **경로 조회** — 출발·도착 좌표 → 대중교통/도보 소요시간·환승·요금.

ULTSPOT에 필요한 것: (2)는 검수 단계와 주변 추천에, (3)은 일정 계산에, (1)은 결과 확인에 쓴다. 우선순위는 **3 > 2 > 1**이다. 이동시간이 맞아야 일정이 성립하고, 지도 그림은 외부 링크로도 대체된다.

## 3. 후보 비교

### 카카오맵 (확인함)

2026년 7월 21일부터 **대중교통 경로 조회·도보 경로 조회·자전거 경로 조회·정적 지도 조회** REST API가 추가됐고, 관리자 심사 없이 앱 설정에서 사용 설정만 하면 쓸 수 있다.

- 공지: [신규 API 4종 오픈](https://devtalk.kakao.com/t/api-4/150764) · [무료 쿼터 사전 안내](https://devtalk.kakao.com/t/api-notice-on-new-kakao-map-api-features-and-free-quota-policy/150222)
- 문서: [카카오맵 REST API](https://developers.kakao.com/docs/latest/ko/kakaomap/rest-api) · [지도 URL(링크) 규칙](https://apis.map.kakao.com/web/guide/)

| API | 엔드포인트 | 무료 쿼터(첫 활성화 앱) | 초과 요금 |
|---|---|---|---|
| 대중교통 경로 조회 | `GET dapi.kakao.com/v2/routing/publictraffic` | 일 1,000건 | 건당 10원 |
| 도보 경로 조회 | `GET dapi.kakao.com/v2/routing/walk` | 일 1,000건 | 건당 10원 |
| 자전거 경로 조회 | `GET dapi.kakao.com/v2/routing/bicycle` | 일 1,000건 | 건당 10원 |
| 정적 지도 조회 | `GET dapi.kakao.com/v2/maps/staticmap` | 일 1,000건 | 건당 2원 |
| 주소로 좌표 변환 | `GET dapi.kakao.com/v2/local/search/address.json` | 기존 제공량 유지 | 기존 정책 |
| 키워드/카테고리 장소 검색 | `GET dapi.kakao.com/v2/local/search/keyword.json`, `.../category.json` | 기존 제공량 유지 | 기존 정책 |

무료 쿼터는 **개발자 계정 기준 첫 번째 활성화 앱**에만 준다. 두 번째 앱부터 또는 초과 시 비즈월렛 연결 + 유료 API 사용 설정이 필요하다. 인증은 전부 `Authorization: KakaoAK ${REST_API_KEY}` 헤더 → **서버에서만** 부른다.

ULTSPOT에 맞는 점:
- 대중교통 응답에 `totalTime`(초), `transfers`, `fare.value`(원), `steps[].type`(BUS/SUBWAY/WALKING), `stops[].name`, `properties.landingURL`(카카오맵 길찾기 화면)이 있다. 우리가 필요한 값이 그대로 있다.
- 장소 검색에 `category_group_code`가 있다: `FD6` 음식점, `CE7` 카페, `AT4` 관광명소, `SW8` 지하철역. 중심 좌표 + `radius`(최대 20km) + `sort=distance`. 주변 식당·휴식·관광 후보를 만드는 데 그대로 쓸 수 있다.
- 정적 지도는 서버가 이미지로 받아 오므로 브라우저에 키를 내보내지 않아도 지도를 보여줄 수 있다. 카카오 CI 로고는 제거 불가(문서 명시) — 위치만 조정한다.

주의:
- 대중교통 응답 `status`가 `STARTNODES_NULL`·`ENDNODES_NULL`·`EQUAL_POINTS`·`NO_RESULTS`일 수 있다. 실패를 0분이나 추정값으로 바꾸면 안 된다.
- **결과를 DB에 영구 저장해도 되는지는 아직 확인하지 않았다.** 카카오 오픈서비스 이용약관을 읽고 판단할 때까지 단기 캐시(같은 요청 재조회 방지)만 쓰고, 공개 카탈로그 필드로 굳히지 않는다.
- 일 1,000건은 넉넉하지 않다. 6곳 선택이면 구간 조합이 최대 30개, 출발/종료까지 42개다. 캐시와 조회 상한이 필수다.

Google Maps는 한국에서 대중교통만 부분 제공하고 자동차·도보·자전거 길찾기를 제공하지 않는다([BGR 정리](https://www.bgr.com/2207179/why-google-maps-doesnt-work-south-korea/), 2026-04). 외국인 팬을 위한 영어 UI에서 Google 링크는 계속 제공하되, **일정 계산의 근거로 쓰지 않는다.**

### 결정

1순위 **카카오맵 REST API** 하나로 경로·지오코딩·주변 검색·정적 지도를 모두 덮는다. 제공자가 하나면 좌표계(WGS84)와 약관 판단이 단순해지고, 심사 없이 시작할 수 있다.
2순위 **ODsay**는 대중교통 품질 비교용으로 남긴다. 카카오 경로가 부실한 구간이 확인되면 그때 요금을 확인하고 붙인다.
지도 표시는 **정적 지도(서버 경유)** 로 시작한다. 브라우저 SDK를 쓰면 JavaScript 키가 노출되고 도메인 등록 관리가 붙는다. [제출 요건](submission-requirements.md)의 "API 키는 서버에만"과도 맞다.

## 4. 키 없이 먼저 만드는 것 / 키가 필요한 것

| 구분 | 내용 | 상태 |
|---|---|---|
| 키 없이 | `Coord` 타입, `FanEvent.coord`, 출발/종료 위치, 이동수단을 데이터 모델과 저장본에 넣는다 | T-019에서 구현 |
| 키 없이 | 구간별 이동시간 계약(`known` / `unconfirmed`)과 그 결과로 일정을 계산하는 엔진 | T-019에서 구현 |
| 키 없이 | 조회 실패·좌표 없음일 때 **이동시간 미확인**으로 표시하고 카카오맵 길찾기 링크로 직접 확인 경로를 주기 | T-019에서 구현. `map.kakao.com/link/by/{traffic\|walk}/...`는 키가 필요 없다 |
| 키 없이 | 날짜별 운영 예외(`dateOverrides`)로 공휴일 휴관·단축 운영 반영 | T-019에서 구현 |
| 키 없이 | 좌표 검수 절차: 조회 결과를 사이드카 JSON으로 남기고 사람이 확인한 뒤 카탈로그에 넣는다 | T-019에서 CLI 준비 |
| **키 필요** | 실제 대중교통/도보 소요시간 (`KAKAO_REST_API_KEY`) | 키 발급 후 |
| **키 필요** | 주소 → 좌표 변환 실행 | 키 발급 후 |
| **키 필요** | 주변 식당·카페·관광 후보 검색 | 키 발급 후 |
| **키 필요** | 정적 지도 이미지 | 키 발급 후 |
| **약관 확인 필요** | 조회 결과를 얼마나 오래 저장해도 되는지, 화면 표기(출처·로고) 의무 | 카카오 오픈서비스 이용약관 확인 전까지 단기 캐시만 |

키가 없는 지금 상태에서 **모든 구간은 `unconfirmed`** 다. 이것이 정상 동작이고, 화면은 이 상태를 숨기지 않는다.

## 5. 발급 절차 (사용자 조치)

1. [카카오디벨로퍼스](https://developers.kakao.com)에서 애플리케이션을 만든다.
2. [앱] > [제품 설정] > [카카오맵] 에서 사용 설정을 켠다. 심사는 없다.
3. [앱 키]의 **REST API 키**를 `.env.local`의 `KAKAO_REST_API_KEY`에 넣는다. `NEXT_PUBLIC_`을 붙이지 않는다.
4. Vercel 프로덕션에도 같은 이름으로 환경 변수를 등록한다.
5. 무료 쿼터(일 1,000건)를 넘길 계획이면 비즈월렛 연결 + 유료 API 사용 설정을 한다. 넘기지 않을 계획이면 조치가 필요 없다.

키를 대화나 커밋에 붙이지 않는다.
