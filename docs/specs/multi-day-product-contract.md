# 여러 날 여행·장소 추가 계약 초안

사용자 요청: 2026-09-20. 제공된 트리플 이미지의 Day 탭·날짜별 지도/일정 구성을 참고했다. 트리플 최신 기능에 대한 조사나 동일 UI 복제 요구로 해석하지 않는다.
상태: 초기 제품 계약. T-028에서 일정·저장 라이브러리를 구현했다. 실제 구현 범위와 별도 저장 테이블 결정은 [journey-storage](journey-storage.md)를 따른다. UI/지도 통합과 자동 날짜 배정은 미완료다.

## 사용자 흐름

1. 시작일과 종료일 선택. 같은 날도 허용. 날짜 수는 포함 계산, 예: 9/21~9/23 = 2박 3일. 이 표기는 숙박 예약 완료를 뜻하지 않는다.
2. 좋아하는 아티스트·필수 행사 선택. 날짜가 고정된 행사는 가능한 날짜에 우선 배정하고, 예약 여부/시각이 불명확하면 사용자가 확인하도록 표시한다.
3. 여행 전체의 담은 장소 목록과 Day 1, Day 2… 탭. 각 날짜에 행사·식당·일반 카페·관광/쇼핑·직접 추가 장소를 배치한다.
4. 날짜별 지도와 방문 순서. 선택한 날짜의 경로를 기본 표시하고 번호를 일정 목록과 맞춘다. 조회하지 못한 이동은 선으로 그려 정확한 경로처럼 보이지 않도록 한다.
5. 장소 추가는 검색해서 추가 / 추천 후보에서 추가 / 직접 입력으로 추가. 지도 표시, 장소 검색, 주변 후보 추천, 길찾기는 서로 다른 기능이다. 카카오 경로 API 연결만으로 식당 목록이 생기지 않는다.
6. 각 방문의 체류시간·고정시각·날짜 변경·순서 변경·삭제 지원. 드래그 외에도 이동 메뉴로 모바일·키보드 접근을 제공한다. 재계산 시 사용자가 고정한 방문을 임의 삭제하지 않는다.
7. 날짜별 활동 시간·선택적 출발/종료 위치 설정. 숙소 좌표는 입력된 경우만 사용하며 미입력 시 전날 마지막 지점을 다음 날 출발로 가정하지 않는다.
8. 저장→새로고침 복원→내보내기 모두 전체 여행을 다룬다. 조회 중 입력이 바뀌면 이전 응답을 폐기한다.

## 데이터와 계산

- 여행 범위: startDate/endDate/timezone(현재 서울 범위 Asia/Seoul), 날짜별 days, 미배정 장소 목록.
- 장소와 방문 분리: placeId와 visitId를 나눠 같은 식당을 다른 날 방문해도 중복으로 거부하지 않는다. 행사 고유 ID는 유지한다.
- Day: date, start/end, origin/destination, visits. Visit: visitId, placeId, stayMinutes, lockedTime 여부/시각, 사용자 순서. 원문 개인 입력은 번역하지 않는다.
- 자료 신뢰: 검수 카탈로그/공급자 검색 결과/사용자 입력을 구분한다. 검색 결과를 검수 카탈로그로 승격하지 않는다. 시간 미확인은 후보 추가를 막는 대신 자동 편성 가능 여부와 충돌 설명으로 구분한다.
- 운영시간·휴무·행사 기간·예약을 날짜마다 검사한다. 식사 체류시간을 행사 체류시간과 공유하지 않는다. 시간 없는 개인 장소도 보관하되 확정 방문시각을 생성하지 않는다.
- 여행 전체를 팩토리얼 탐색하지 않는다. 고정 행사를 날짜에 배치하고 주변 후보를 날짜별로 좁힌 뒤 기존 일일 계산을 사용한다. 기존 6개 탐색 한도는 사용자 전체 저장 장소 한도와 분리한다. 초과 시 자동 최적화 범위를 명시하고 수동 일정은 유지한다.
- 지도 행렬도 날짜별 후보로 제한. 날짜가 달라도 영구 동일한 대중교통 시간으로 캐시하지 않는다. API가 미래 출발시각을 지원하지 않으면 조회 시각과 참고값임을 표시한다. Jev는 검수 후보의 취향 순위에만 사용한다.

## 저장 호환성 — 먼저 해결

현재 SavedTrip.version=1과 input.date는 하루 구조이며 Supabase guest_trips의 JSON CHECK도 version=1만 허용한다. 프런트 버전만 2로 바꾸면 클라우드 저장이 실패한다.

- v1을 하루짜리 v2로 읽는 명시적 변환을 추가한다. 개인 행사 원문·선택·아티스트를 유지한다.
- v2 parser는 날짜 연속성/중복 visitId/참조/개인 메타데이터 주입/크기 제한을 검사한다.
- T-028 결정: 기존 guest_trips CHECK는 변경하지 않고 guest_journeys 전용 테이블을 추가한다. 구버전 writer가 새 초안을 덮어쓰는 것을 막는다. RLS와 64KiB 상한은 유지한다.
- 여러 날 데이터를 구버전이 읽지 못할 때 빈 초안으로 덮어쓰지 않도록 한다. 로컬 저장 키 전환과 롤백 방침도 함께 둔다.
