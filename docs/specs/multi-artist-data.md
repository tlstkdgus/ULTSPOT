# 여러 아티스트 지원과 수집 데이터 반영 계획

T-011 구현: `/plan` Your spots에서 공식 프로필 확인 11개 아티스트의 검색·최대 5개 선택·저장·공통 장소 안내를 제공한다. 관계 부분 날짜와 회차/예매 구간 선택 탭도 추가했다. [현재 범위·출처·제약](../data/catalog-conditions.md). 아래 T-010/T-009의 미구현 표시는 해당 시점 기록이며 이번 구현 범위가 우선한다.

T-010 첫 수집: 아티스트 208·소속 관계 222·장소 6·종료 행사 5건을 접수했다. 전부 검수 대기이며 공개 반영은 하지 않았다. [검토 보고서와 보완 우선순위](../data/first-collection-review.md)에 따라 현재/예정 행사·현재 운영 장소와 공식 아티스트 근거를 보완한다. 부분 날짜 정밀도와 회차·예매 유형별 조건은 모델 확장이 필요하며 임의 단일 값으로 변환하지 않는다.

T-009 구현: [수집 파일 검증·비공개 적재](../data/intake.md)를 추가했다. 공개 카탈로그·아티스트 선택 UI는 아직 미구현이다. 수집 원본은 `.local-data/incoming/`에 전달한다.

2026-09-19 · T-006 · 사용자 결정: 여러 아티스트의 데이터를 외부 수집 담당자가 확보한다. 특정 그룹에 한정하지 않는다.

이 문서는 향후 제품·데이터 계약이다. 현재 동작은 [실제 비회원 플래너](public-planner.md)가 기준이다. 기존 문서의 스트레이 키즈·특정 구역 한정은 초기 조사 사례로만 남기며 제품 제한으로 적용하지 않는다. 가상 행사 제출 방침은 T-005에서 이미 철회됐다.

## 제품 범위와 흐름

여행 날짜·도시 → 아티스트 검색·복수 선택(그룹/멤버/유닛/솔로 구분) 또는 전체 K팝 탐색 → 여행 기간에 맞는 검수 행사·장소 → 방문 조건 확인 → 일정 생성·수정 → 저장.

- 한글·공식 영문·별칭으로 같은 엔티티를 찾는다. 동명이인은 그룹·유형으로 구분한다.
- 복수 선택은 OR로 후보를 합치되 동일 행사·장소는 한 번만 표시한다. 맞는 아티스트를 카드에 표시한다.
- 그룹 선택은 그룹 직접 연결과 소속 멤버·유닛 연결을 탐색 범위에 포함한다. 개인 선택은 개인 직접 연결과 해당 그룹·유닛 전체 행사를 포함하되 다른 멤버만의 행사는 제외한다. 과거 소속·불명확한 관계는 자동 확장하지 않는다.
- 그룹 전체 행사가 특정 개인 관련 검색에 포함돼도 그 개인의 참석을 보장하지 않는다. 연결 근거를 표시한다.
- 결과가 없으면 해당 조건의 검수 데이터가 부족하다고 안내한다. 날짜/아티스트 변경 또는 공통 K팝 장소를 제시하되 공통 장소를 최애 관련 행사로 포장하지 않는다.
- 로그인 없는 핵심 기능 접근을 유지한다. 수집 담당자 승인 도구는 일반 방문자의 공개 입력과 분리한다.

## 데이터와 승인

[수집 요청서](../data/collection-brief.md)의 10개 탭이 납품 계약이다. 아티스트·소속 관계·장소·행사·연결·운영 구간·특전·출처·권리 정보를 분리한다. 공통 장소는 아티스트 연결이 없어도 된다. 수집 자료는 별도 대기 영역에 넣고 승인 전 공개 카탈로그에 반영하지 않는다.

임포트는 필수 컬럼, enum, 날짜·시각, ID 유일성, 관계 참조, HTTPS 출처, 시간 구간, 출처·권리 상태를 검증한다. 행별 오류 보고 후 재납품을 받는다. 같은 ID 재반입은 중복 생성하지 않고 변경 이력과 검수 상태를 갱신한다. 승인 데이터 수정은 재검수하며 삭제·취소는 공개 목록과 이후 일정 재계산에 반영한다.

수집 경로는 직접 제공·허용된 공식 자료·공공데이터를 포함하며 X API에 단독 의존하지 않는다. 플랫폼/API별 적용 약관 검토 전 자동 수집·AI 이미지 처리·재배포를 승인된 것으로 간주하지 않는다. AI는 검수 전 추출·번역 초안에 사용 가능하며 사람이 확인한 사실을 대체하지 않는다.

## 구현 순서와 수용 기준

| 순서 | 필요한 구현 | 수용 기준 |
|---|---|---|
| 1 | 데이터 모델·수집 파일 검증·승인 도구 | 깨진 관계·중복·날짜 오류를 행 번호와 함께 보고, 미승인 데이터 공개 0건 |
| 2 | 아티스트 검색·선택·관련성 필터 | 한글/영문/별칭 일치, 그룹/멤버/유닛 관계, OR 중복 제거, 빈 결과 안내 검증 |
| 3 | 검수 카탈로그 연결·상세 카드 | 행사/매장 시간 구분, 출처·확인일·예약·비용·특전 조건 표시 |
| 4 | 일정 엔진 확장 | 날짜별 예외·복수 운영 구간·휴식·자정 종료 검증. 미확인 시간과 취소 행사 제외 |
| 5 | 운영 갱신·AI·교통 API 연결 | 취소·변경 재검수 및 재계산, AI 평가, 교통 데이터 이용 조건·실패 처리 검증 |

데이터 양은 확보 결과로 결정한다. 특정 그룹의 표본을 전체 서비스 커버리지로 홍보하지 않는다. 아티스트별 검수 행사 수·날짜/지역 범위·출처 누락·재확인 기한 초과를 내부 품질 지표로 관리한다.

## 현재 구현과 차이

현재 FanEvent는 단일 주소·기간·하루 운영 구간·요일 휴무·예약 boolean·출처 하나를 지원한다. 아티스트 ID/관계, 관리자 임포트·승인, 날짜별 복수 구간, 특전 구조화는 없다. 수집 명세를 기존 타입에 무손실 저장할 수 있다고 주장하지 않는다. DB migration과 UI·엔진 구현을 후속 태스크로 수행하고 미지원 조건을 잘라내지 않는다.

현재 클라우드 guest_trips는 개인 일정 저장용이다. 공용 아티스트·행사 DB와 검수 권한으로 재사용하지 않는다. 개인 사용자가 입력한 행사도 자동으로 공용 카탈로그에 공개하지 않는다. 이번 문서 작업은 런타임·DB·환경 변수 변경과 외부 데이터 반입을 수행하지 않는다.
