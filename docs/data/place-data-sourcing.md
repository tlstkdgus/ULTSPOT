# 장소 데이터 확보 방안 — 조사 결과 (2026-09-17)

> **T-006 수집 기준 갱신:** 아래는 당시 특정 그룹 조사와 정책 검토의 이력이며 최신 약관의 보증이 아니다. 현재 팀 수집은 [여러 아티스트 데이터 요청서](collection-brief.md)와 [전달 프롬프트](collection-prompt.md)를 사용한다. X API는 가능한 경로 중 하나다. 직접 제공·허용된 공식 원문·공공데이터도 검토하며, 플랫폼별 최신 수집·저장·AI 처리·표시 권한은 반입 전에 확인한다. 제3자 전달·판매는 별도 검토 사항이다.

> 대상: 기획안 v0.4 §7.2 데모 데이터 — 스트레이 키즈, 서울, 생일카페·팝업(기간 한정) + 상설 덕질 장소(촬영지, 멤버 방문 식당)
> 결정 (사용자, 2026-09-17): **팬 이벤트는 X API로 수집한다.**
> 이 문서는 법률 자문이 아니라 조사 요약이다.

## 1. 결론 요약

| 데이터 | 확보 방법 | 이유 |
|--------|-----------|------|
| 생일카페·팬 이벤트 (기간 한정) | **X API** → 포스터 이미지 AI 추출 → 사람 검수 | 원출처가 주최자 X 게시물. 공개 API·공공데이터 없음. 기획안 가정 1(포스터 추출)과 같은 경로 |
| 공식 팝업 | X API(공식 계정) + 기사 | 네이버 지도 팝업 정보는 공개 API로 나오지 않음 (§4) |
| 상설 장소 (촬영지·방문 식당) | 수작업 큐레이션 + 출처 2개 이상 교차 확인 | 방송·기사·공식 계정의 사실 정보. 블로그 오류가 많음 (§6) |
| 주변 식당·카페·관광지 | **한국관광공사 TourAPI** | 무료, "이용허락범위 제한 없음" |
| 주소 → 좌표, 영업시간 | 지도 API 1종 (약관 확인 후 선택) | §4 참고 |

**하지 않는다:** 덕플레이스·팝가 크롤링·내부 API 호출·수동 복제 (§2)

## 3. X API — 확인한 조건

출처: docs.x.com (2026-09-17 열람)

| 항목 | 내용 |
|------|------|
| 요금 | **pay-per-usage, 선불 크레딧** (Developer Console에서 구매). 신규 개발자에게 무료 티어·월정액 없음 |
| 단가 | 게시물 읽기 **$0.005/건**, 사용자 조회 $0.010/건 |
| 중복 | 같은 리소스는 **UTC 하루(24시간) 안에서 1번만 과금** |
| 한도 | 게시물 읽기 월 300만 건 |
| 최근 검색 | **최근 7일**, 요청당 최대 100건 |
| 전체 기간 검색 | **pay-per-use에서 사용 가능**, 요청당 최대 500건 |
| 쿼리 연산자 | `#해시태그`, `lang:`, `has:images`, `-is:retweet` 등 |

> 서드파티 블로그들은 읽기 단가·월 한도를 다르게 적고 있다 ($0.005, 200만~300만 건). 위 표는 공식 문서 기준.

### 개발자 정책에서 설계에 영향을 주는 조항

| 조항 (docs.x.com/developer-terms/policy) | ULTSPOT 설계 |
|---|---|
| X 콘텐츠를 저장하면 X의 현재 상태와 맞춰야 하고, 삭제·수정되면 합리적으로 빠르게 또는 요청 후 24시간 안에 반영 | **게시물 ID를 저장**하고, 추출한 이벤트마다 원 게시물 ID를 연결. 원문이 삭제되면 이벤트도 내린다 (주기적 재확인) |
| X for Websites(임베드)를 쓰지 않으면 API로 최신 버전을 받아 표시 | 원문은 **임베드 또는 링크**로만 보여준다. 게시물 본문을 우리 DB에서 꺼내 그대로 재게시하지 않는다 |
| 제3자에게 X 콘텐츠를 제공할 때는 게시물·사용자 ID만 배포 가능 | **B2B·B2G 데이터 판매(기획안 §5.2)에 X 유래 데이터를 넣지 않는다.** 판매 데이터는 우리 서비스의 체크인·방문 기록만 |
| 위치 데이터 단독 사용 금지, 오프-X 매칭은 명시적 동의 필요 | 주최자·팬 계정을 우리 사용자와 연결하지 않는다 |

**확인 못 한 것:** 게시물에서 AI로 "추출한 사실(날짜·주소·특전)"을 저장하는 것이 위 동기화 의무의 범위에 드는지. 보수적으로 원 게시물 ID와 묶어 동기화한다.

### 수집 흐름 (제안)

```
1) 검색    전체 기간 검색 (알림 게시물은 이벤트 1~3주 전에 올라오므로 7일 검색만으로는 부족)
           예: (생일카페 OR 생카 OR "birthday cafe" OR 컵홀더) (승민 OR Seungmin OR 필릭스 OR Felix) has:images -is:retweet
2) 추출    포스터 이미지 → 멀티모달 AI → {카페명, 주소, 기간, 운영시간, 특전, 조건} + 신뢰도
3) 검수    사람이 원문과 대조 (기획안 가정 1 — 추출 정확도 — 의 측정 데이터가 된다)
4) 좌표    주소 → 지도 API (§4)
5) 저장    event ↔ x_post_id, 원문 링크 병기
6) 동기화  표시 전 또는 매일 원 게시물 존재 확인, 삭제되면 비공개
```

**비용 추정:** 게시물 2,000건 읽기 × $0.005 = **약 $10**. 멤버 2명(필릭스·승민)·9월 범위라면 이 안에 든다 (추정, 실측 전).

**사용자 준비물:** X Developer Console 가입 → 크레딧 구매 → Bearer Token → Vercel·로컬 환경 변수 `X_BEARER_TOKEN` (서버 전용, `NEXT_PUBLIC_` 금지)

## 4. 네이버 지도 · 구글 지도 — 팬 이벤트를 따로 정리하나?

| 서비스 | 정리 여부 | API로 가져올 수 있나 |
|--------|-----------|----------------------|
| **네이버 지도·플레이스** | **팝업스토어는 정리한다.** 2025년 5월 스마트플레이스에 팝업스토어 업종 추가, 6월 26일부터 지도·플레이스·통합검색·발견탭에 노출. 사업자가 운영 기간, 사전 예약, 굿즈 등을 직접 등록. 팝가와 제휴해 팝가 등록 팝업이 최대 1일 안에 네이버 지도에 반영 | 팝업 목록·기간을 주는 **공개 API는 찾지 못함.** 검색 API(지역 검색)는 최대 5건, 팝업 기간 필드 제공 여부 미확인 |
| 네이버 — 생일카페 | **별도 업종·카테고리 없음.** 생일카페는 팬이 기존 카페를 며칠 대관하는 형태라 장소는 "카페"로만 존재 | 대관 카페의 주소·좌표 확인 용도로만 가능 |
| **구글 지도** | 생일카페·팬 이벤트를 따로 정리하지 않음. 팬들이 만든 개인 저장 목록은 있으나 API로 제공되지 않음 | Places API로 **장소 정보(주소·좌표·영업시간)만** |
| 해외 팬이 실제로 쓰는 곳 | Offmate, Saengca Day, Dukplace 같은 전용 앱·사이트 | 공개 API 없음 |

**지도 API 선택 시 확인할 것 (이번에 약관 원문 확인 안 함):** 검색 결과를 DB에 저장·캐시해도 되는지, 외국인 대상 영어 표기 품질, 비용.
