# X 팬 이벤트 수집·분류 계획 (T-065)

> 2026-09-25 작성. X를 연결하기 **전**에 정한 설계다. 키워드와 검색어는 실제 X 응답으로 아직 검증하지 않았다 —
> 연결 후 첫 수집에서 결과를 보고 고친다. 원칙(원출처·검수·삭제 동기화·판매 금지)은
> [place-data-sourcing.md §3](place-data-sourcing.md)과 정책 "외부 이벤트 데이터 운영"을 그대로 따른다.

## 1. 무엇을 모으나

생일카페가 중심이다. 공지가 거의 X에만 올라오고(주최자 계정 + 포스터 이미지), 날짜·운영시간·특전이 있어 일정에 넣을 수 있다.

| 분류 | 예 | 우리 장소 분류 |
|---|---|---|
| 생일카페·컵홀더 이벤트 | "최예나 생일카페 in 홍대 9/27~29" | `birthdayCafe` |
| 팝업·전시 | 공식 팝업스토어, 팬 전시회 | `popup` |
| 촬영지 | 뮤비·예능 촬영지 | `filming` |
| 광고·서포트 | 생일 지하철 광고, 전광판 | `support` — 2026-09-25 사용자 결정으로 추가(T-070). 첫 데이터: 필릭스 합정역 CM보드(보도 기사) |
| 제외 | 양도·판매·교환·공구, 숙소·자택·출퇴근길 | 모으지 않는다 |

## 2. 검색어 — `scripts/catalog/x-query.mjs`

아티스트마다 하나씩 만든다: **이름·한국어 이름·별칭 중 하나 AND 이벤트 용어 중 하나**, 사진 있는 원글만, 거래 글 제외.

```
(최예나 OR YENA OR 예나 OR "Choi Yena" OR "Choi Ye-na")
(생일카페 OR 생카 OR "생일 카페" OR 컵홀더 OR "컵홀더 이벤트" OR ... OR "birthday cafe" OR cupsleeve ...)
has:images -is:retweet -is:reply -(양도 OR 판매 OR 대리 OR 구해요 OR 구합니다 OR 교환)
```

- **기간:** 생일 21일 전 ~ 3일 뒤(`birthdayWindow()`). 공지는 보통 1~3주 전에 올라오고 카페는 생일 전후 며칠 연다.
  생일이 있는 아티스트(검수 목록 23명 + 이번 솔로 15명)부터 한다.
- **길이:** X 검색어 한도(512자)를 넘으면 별칭부터 줄인다.
- **키워드 사전** (`EVENT_TERMS`·`PERK_TERMS`·`EXCLUDE_TERMS`):
  - 이벤트: 생일카페, 생카, 생일 카페, 컵홀더, 생일 이벤트, 카페 이벤트, birthday cafe, cupsleeve / 팝업, 팝업스토어, 전시회, 포토존 /
    촬영지, 성지순례 / 생일광고, 지하철 광고, 전광판, 서포트
  - 특전(추출 대상): 컵홀더, 포카·포토카드, 럭드·럭키드로우, 선착·선착순, 엽서, 스티커, 인생네컷·포토부스
  - 제외: 양도, 판매, 대리, 구해요, 교환, 공구, 분철, 급처, 삽니다, WTS·WTB
- **해시태그**(검색어에 추가 후보, 첫 수집에서 효과 확인): `#{이름}_생일카페`, `#{이름}생카`, `#HAPPY_{NAME}_DAY`, `#{NAME}DAY`
- **카페 계정 역방향:** 생일카페 대관을 반복하는 카페 계정(예: 홍대 `@cafe_NITA`·`@tone_manner077`, 부산 `@note_344`)은
  `from:` 검색으로 한 번에 여러 아티스트의 이벤트를 찾는다. 계정 목록은 첫 수집에서 자주 나온 대관처로 만든다.

## 3. 수집 → 분류 → 검수 흐름

```
1) 검색   아티스트별 검색어 × 생일 기간 → 게시물 ID·작성자·본문·이미지 URL (본문은 검수 뒤 지운다)
2) 1차 분류  classifyPost(): 거래·사생활 → 버림 / 이벤트 용어로 분류 / 특전 표시 / 아티스트 후보
3) 추출   포스터 이미지 → Qwen3.8-27B(HF) → {카페명, 주소, 기간, 운영시간, 특전, 참여 조건} + 필드별 근거·신뢰도  (pnpm data:extract)
4) 좌표   주소 → 카카오 주소 검색(pnpm data:geocode) → 좌표. 주소가 없거나 안 맞으면 검수로
5) 검수   사람이 원문·포스터와 대조. 승인/보류/제외. 사생활 장소·출처 불명은 제외
6) 게시   승인분만 카탈로그에 (provenance: 게시물 URL, 수집일)
7) 동기화 매일 원 게시물 존재 확인 → 삭제·비공개면 24시간 안에 내림, 날짜·주소 수정이면 재검수
```

### 분류 규칙

- **주최 공지 vs 퍼 나르기:** 사진 있는 원글(리트윗·답글 아님)을 주최 공지 후보로 본다. 인용·답글은 주최 계정을 찾는 단서로만 쓴다.
- **아티스트 매칭:** 우리 아티스트 목록(이름·한국어 이름·별칭)으로 찾는다. **두 글자 별칭**(예나·유리)은 다른 사람과 겹쳐 약한 신호로
  따로 둔다(`weakArtistIds`). 약한 신호는 (a) 생일 기간 안의 게시물이거나 (b) 그룹명·풀네임이 같이 나올 때만 올린다.
- **같은 이벤트 합치기:** 같은 아티스트 + 같은 카페(주소 좌표 100m 안) + 기간이 겹치면 하나로 합친다. 가장 이른 주최 게시물을 원출처로 둔다.
- **여러 아티스트:** 합동 생일카페는 아티스트를 모두 연결한다.
- **분류 없음:** 이벤트 용어가 없는 사진 원글은 "분류 없음" 대기열로. 버리지 않는다(포스터에만 글자가 있는 경우가 많다).

### 추출 모델 (T-071, 2026-09-25 결정)

사용자 요청 "AI 모델은 huggingface 등에서"에 따라 Hugging Face Inference Providers(`router.huggingface.co`, OpenAI 호환)로 부른다.
구현: [`scripts/catalog/poster-extract.mjs`](../../scripts/catalog/poster-extract.mjs), 실행 `pnpm data:extract <포스터> [본문.txt] [연도]`.

| 역할 | 모델 | 고른 이유 (2026-09-25 HF에서 확인) |
|---|---|---|
| 기본 | [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) | 이미지 입력 기본 지원, OmniDocBench 1.5 91.1, Apache-2.0, 추론 제공자 5곳 live |
| 대체 | [google/gemma-4-31B-it](https://huggingface.co/google/gemma-4-31B-it) | Apache-2.0, 제공자 3곳 live. 기본 모델 404·5xx일 때 한 번 |
| 제외 | GLM-OCR·Nemotron OCR 등 OCR 전용 | 글자는 잘 읽지만 기간·주소·특전으로 나누지 않고, GLM-OCR은 HF 제공자에서 live가 아니었다 |

- 출력은 JSON 스키마(strict)로 받고, 받은 뒤 다시 검사한다. 날짜가 실제 날짜가 아니거나, 시각이 HH:MM이 아니거나, 자정을 넘기면 그 필드를 비우고 이유를 남긴다.
- 필드마다 **근거 문구와 신뢰도**를 받는다. 근거가 없거나 신뢰도가 0.7 미만인 필드는 `needsReview`로 사람 검수에 넘긴다.
- 결과는 `.local-data/extract/`(git 제외) 사이드카에만 쓴다. 카탈로그에 자동으로 넣지 않는다.
- 키: `HF_TOKEN`(fine-grained, "Make calls to Inference Providers" 권한). 스크립트를 돌리는 사람의 `.env.local`에만 둔다. Vercel·앱 서버에는 넣지 않는다.
- **아직 실제 포스터로 돌리지 않았다**(토큰 없음). 가짜 응답으로 요청 형식·검사·대체 경로만 확인했다. 연결 후 첫 5명 포스터로 정확도와 토큰 비용을 잰다.

## 4. 비용 (추정)

X API는 2026년부터 쓴 만큼 내는 방식이다. 게시물 읽기 1건 $0.005, 월 300만 건 상한, 같은 게시물은 하루(UTC) 안에 다시 읽어도 한 번만 과금된다.

| 가정 | 값 |
|---|---|
| 아티스트 1명의 생일 기간 검색 결과 | 50~300건 |
| 아티스트 1명 1회 비용 | 약 $0.25~$1.5 |
| 생일 있는 38명 1년 | 약 $10~$60 |
| 아티스트 전체 243명으로 넓히면(생일 확인 후) | 약 $60~$360/년 |

추정치다. 첫 수집 5명으로 실제 건수를 재고 고친다. 월 예산 상한을 X 콘솔에 먼저 건다.

### 광고·서포트 수집 (T-070)

생일 광고는 X 외에 **모금 플랫폼 공지와 보도 기사**로 확인되는 경우가 많다(블립 서포트, 애드포스타, 팬앤스타 등 —
목표 달성 시 지하철·전광판 광고). 역·광고판 이름(예: "합정역 CM보드")까지만 나오고 호선·출구가 없으면
좌표는 역을 가리키게 두고 "역 안 위치 미확인"을 문구에 적는다. 송출 시간을 모르면 운영시간은 null(자동 편성 제외).

## 5. 연결 뒤 바로 확인할 것

1. **전체 기간 검색(`/2/tweets/search/all`)이 쓴 만큼 요금제에서 되는지.** 요금 문서에 구분이 없다. 안 되면 최근 7일 검색만 가능해
   "생일 21일 전부터" 창을 매일 조금씩 훑는 방식으로 바꾼다.
2. 검색어 한도(512자)와 연산자(`has:images`, `-is:reply`) 지원 여부.
3. 첫 5명(최예나·박지훈·필릭스·승민·조유리)으로 1차 분류 정확도: 생일카페로 분류된 것 중 실제 생일카페 비율, 놓친 공지 수.

## 6. 정하지 않은 것 (사용자 결정)

- HF 사용 한도(월 크레딧 상한). 제공자 요금은 호출마다 `usage` 토큰으로 남으니 첫 수집 뒤 정한다.
- 수집 대상 아티스트 우선순위와 월 예산 상한.
