## 결정

- 빈 구간(최대 3개)을 **동시에** 채운다. 구간마다 장소 검색 + 이동시간 조회를 기다리므로, 순서대로면 구간 수만큼 늦었다.
  이제 가장 긴 구간만큼만 걸린다. 한 구간 안의 이어 붙이기(식사 → 카페 → 관광)는 앞 장소에서 출발하므로 여전히 차례로 간다.
- 동시에 돌면 두 구간이 같은 가게를 고를 수 있다. **고르는 순간 선점(claim)**한다 — 자바스크립트는 한 스레드라
  확인과 등록 사이에 끼어드는 일이 없다. 선점에 밀린 구간은 그 가게들을 빼고 한 번만 다시 찾는다.
- 다른 구간이 이미 고른 곳은 검색 요청에서부터 뺀다(선점 확인은 여전히 claim이 한다).
- 실행부(`fillGap`·`fillChain`)를 `src/lib/trip/gap-fill-run.ts`로 옮겨 React 없이 검사할 수 있게 했다.

## 하지 않은 것

- 서버 쪽 병렬화. 추천 라우트는 이미 카카오·TourAPI를 동시에 부른다(T-050).

## 검증

- 신규 `e2e/gap-parallel.spec.ts`(가짜 fetch, 응답당 80ms): 두 구간을 동시에 채워도 같은 가게 0건, 300ms 안에 끝남
  (순서대로면 최소 320ms). 세 곳을 빼앗긴 구간은 다시 찾아 네 번째를 받는다.
- E2E 전체 **459건 통과 · 3 skip · 0 실패**
- 실데이터 캡처: 결과가 T-051과 같다(왕비집 → 세종갤러리 → 더 스팟 패뷸러스)
