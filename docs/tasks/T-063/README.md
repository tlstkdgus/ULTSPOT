## 결정

- 당일 일정과 **같은 빈 시간 채우기**(T-049~T-052·T-061)를 여정의 각 날에도 쓴다. 여정은 사용자가 정한 순서대로
  시각만 계산하므로(scheduleJourneyDay) 그 결과를 채우기 입력(TripResult·TripInput)으로 옮기는 어댑터
  `src/lib/trip/journey-gaps.ts`를 두었다.
- **앞에서부터 시각이 확정된 방문까지만** 쓴다. 이동시간·운영시간 미확인이나 충돌로 시각이 비는 방문이 나오면 그 뒤는
  시각이 없어 빈 시간을 잴 수 없다. 이때 하루의 끝을 끊긴 자리로 당겨 **가짜 "마지막 방문 뒤 빈 시간"을 만들지 않는다.**
- 여정에는 관심사 칩이 없어 추천 순서는 거리순이다. 추천 한 곳의 체류는 60분.
- "이 날의 위치"에 실제 지도를 넣었다(키가 있으면 Google, 없으면 카카오). 확정 방문은 번호, 추천은 주황.
- 추천이 들어간 다음 방문의 이동 구간은 추천 장소에서 출발하는 값으로 바꿔 보여준다.

## 같이 고친 것

- 여정 화면 스펙(journey-ui)이 실제 `/api/recommend`를 불러 분당 상한에 걸리고 recommend.spec이 429로 깨졌다 →
  기본 고정값을 걸었다. `twoNightJourney()`는 추천 고정값을 인자로 받는다.
- gap-parallel.spec이 걸린 시간(300ms 미만)으로 동시 실행을 확인했는데 전체 실행 부하에서 535ms가 나왔다 →
  **동시에 떠 있던 요청 수 ≥ 2**로 바꿨다.
- 여정 캡처가 지도 타일·추천 사진을 기다린 뒤 찍는다.

## 하지 않은 것

- 여정의 "장소 직접 추가" 화면. 문구만 있고 폼이 없다(T-062에서 확인). 저장 형식은 검색 좌표를 받는다.
- 여정의 관심사 입력. 기간 정하기의 관심사 칩을 여정에 저장하지 않는다.

## 검증

  운영시간 모르는 곳에서 멈춤 / 여정 화면에 추천 카드
