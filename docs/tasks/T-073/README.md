## 실제 실행에서 나온 것 → 고친 것

| 증상 | 원인 | 고침 |
|---|---|---|
| 맞게 읽은 제목이 "검수 필요" | 근거 키를 모델이 `event_name`으로 적음(자유 키) | 근거·신뢰도의 키를 필드 이름으로 스키마에 고정 |
| 생일(SEPTEMBER 22, OCT 2ND)이 시작일로 | 생일을 넣을 칸이 없음 | `birthday`(MM-DD) 칸 추가, 프롬프트에 규칙, 날짜 하나면 검수·생일과 같으면 비움 |
| 경민 포스터 응답이 빔 | 생각 토큰이 한도 1,200을 다 씀 | `enable_thinking: false`, 한도 4,000, 잘리면 "토큰 한도" 이유를 따로 남김 |
| HTTP 402에서 원인 모름 | — | 402·429·401/403마다 할 일을 안내 |

## 측정 (7회 호출, 포스터 3장)

아티스트는 3장 모두 맞았고, 지어낸 장소·주소·기간은 0건이었다. 장식 글씨 제목은 3장 모두 한 글자 이상 틀렸다. 그런데 신뢰도는 0.9로 나와서 신뢰도로는 이런 오류를 걸러낼 수 없다. 토큰은 장당 2,300~3,100개였다. 자세한 내용은 [x-collection-plan](../../data/x-collection-plan.md) "첫 실제 실행"에 있다.

## 하지 않은 것

- 생각 모드를 끈 뒤로는 실제 호출을 하지 못했다. 크레딧이 소진됐기 때문이다(HTTP 402).
- 모델은 바꾸지 않았다. 아티스트 판별과 "모르면 비우기"는 잘했고, 틀린 건 장식 글씨였다. 다른 모델과는 비교해 보지 않았다.
