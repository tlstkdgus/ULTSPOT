## 목표

고정 여유시간 하나로 모든 구간을 계산하던 일정 엔진을 **구간별 실제 이동시간**으로 바꾼다. 키가 없으면 "이동시간 미확인 + 직접 확인 경로"로 정직하게 떨어진다.

## 결정

- **제공자는 카카오맵 REST API 한 곳으로 시작한다.** 2026-07-21부터 대중교통·도보 경로와 정적 지도가 **관리자 심사 없이** 열렸고, 첫 활성화 앱 기준 각 일 1,000건 무료(초과 건당 10원)다. 근거와 다른 후보 비교는 [지도·경로 연동 검토](../../specs/map-and-routing.md).
- **지도 표시는 정적 지도(서버 경유)로 시작한다.** 브라우저 SDK는 JavaScript 키가 노출되고 도메인 등록 관리가 붙는다. [제출 요건](../../specs/submission-requirements.md)의 "API 키는 서버에만"과도 맞다.
- **조회 결과는 단기 캐시(10분)만 한다.** 결과를 DB에 영구 저장해도 되는지 카카오 약관을 확인하지 않았다. 대중교통 소요시간은 시간대에 따라 변하므로 길게 두는 것도 맞지 않다.
- **`unconfirmed`가 기본 상태다.** `TravelEstimate`는 `known`/`unconfirmed` 두 상태뿐이고, 조회 결과가 없는 구간은 `null`로 비우지 않고 사유·여유시간·직접 확인 링크를 담은 `unconfirmed`로 만든다. 화면이 실수로 빈칸을 그리는 일을 막는다.
- **좌표는 검수를 거쳐야 카탈로그에 들어간다.** `pnpm data:geocode`는 사이드카(`request/response/review.json`)만 쓰고 `catalog.ts`를 건드리지 않는다. 지오코딩은 비슷한 주소에 다른 건물을 물어올 수 있다.
- **직선 거리는 이동시간이 아니다.** `straightLineMeters`는 주변 후보 정렬용이고, 분으로 환산하지 않는다(주석·테스트로 고정).
- **날짜별 운영 예외가 요일 휴무보다 우선한다.** `effectiveHours`/`statusOn`을 라이브러리로 내보내, 화면이 요일을 직접 계산하지 않게 한다.

## 확인한 현재 한계 (요청 1)

| 항목 | 이전 | 이후 |
|---|---|---|
| 이동시간 | `input.transfer` 하나를 모든 구간에 동일 적용 | 구간별 조회값, 없으면 여유시간 + 미확인 표시 |
| 첫 구간 | 항상 0분 (11:00 출발이면 11:00에 이미 첫 장소) | `origin`이 있으면 첫 구간 이동시간을 넣는다 |
| 종료 | 없음 | `destination`이 있으면 돌아가는 시간이 종료 시각 안에 들어가야 일정에 넣는다 |
| 이동수단 | 없음 | `travelMode` (`transit`/`walk`) |
| 좌표 | 없음 | `FanEvent.coord`(출처·확인일 포함), 출발/종료 좌표, 한국 범위 검사 |
| 운영 예외 | 요일만 | `dateOverrides`로 공휴일 휴관·단축 운영 |

## 하지 않은 것

- **실제 경로 조회.** `KAKAO_REST_API_KEY`가 없어 모든 구간이 `unconfirmed`다. 카카오 응답 파싱은 문서의 응답 형식으로 단위 테스트했지만 **실제 API 호출은 한 번도 하지 않았다.**
- **좌표 채우기.** 장소 3곳 모두 `coord`가 없다. 추측한 좌표를 넣지 않았다. 키가 생기면 `pnpm data:geocode`로 후보를 뽑아 검수한다.
- **화면 연결.** `src/components/**`는 Claude 담당이라 건드리지 않았다. 두 상태를 어떻게 보여줄지는 [claude-ui-handoff.md](../../claude-ui-handoff.md)의 "T-019 이동시간" 요청에 적었다.
- **지도 표시 구현.** 정적 지도 엔드포인트는 만들지 않았다. 경로가 먼저다.
- 예약 확정 시각으로 일정을 고정하는 처리, 필수 방문지 우선순위, 주변 식당·관광 추천 — 후속 태스크.
- 캡처. UI 변경 없음.

## 보안 메모

`/api/travel`은 **인증 없는 공개 엔드포인트**이고 유료 쿼터를 쓴다. 대신 구간 수 상한(42), 본문 크기 상한(16KiB), 한국 좌표만 허용, IP별 분당 60요청, 프로세스 일일 외부 조회 800건, 성공 응답만 10분 캐시를 넣었다. **한계: 메모리 기반이라 서버 인스턴스마다 따로 센다.** 트래픽이 늘면 공용 저장소로 옮겨야 한다.
