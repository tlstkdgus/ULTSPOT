## 배경

PR #50(T-038·T-039)을 머지하고 프로덕션을 검증하는 과정에서, **PR #49로 들어온 카카오
지도가 프로덕션에서 한 번도 그려진 적이 없었다**는 것을 확인했다. 코드는
`NEXT_PUBLIC_KAKAO_JS_KEY`를 읽는데 Vercel에 등록된 이름은 `KAKAO_JS_KEY`였다.

눈에 띄지 않은 이유가 있다. 키가 없으면 지도를 그리지 않고 핀 목록과 카카오맵 링크로
떨어지도록 `kakao-map.tsx`가 설계돼 있다. 화면이 깨지지 않으니 아무도 몰랐다. 이 우아한
fallback이 동시에 이 결함을 두 PR 동안 숨겼다.

## 조치

- 같은 JS 키를 `NEXT_PUBLIC_KAKAO_JS_KEY`로 프로덕션에 추가하고 재배포했다.
  `NEXT_PUBLIC_`은 빌드 시각에 번들로 들어가므로 변수 추가만으로는 반영되지 않는다.
- `.env.example`에 이 키를 **이름을 지키라는 경고와 함께** 적었다. 애초에 example에 없어서
  이름이 갈라진 것이다. REST 키는 이미 적혀 있었고 JS 키만 빠져 있었다.

## 결정

- **코드를 환경에 맞추지 않고 환경을 코드에 맞췄다.** 반대 방향(서버에서 키를 읽어 내려주기)은
  변경 범위가 커지고, JS 키는 도메인 제한 브라우저 키라 애초에 `NEXT_PUBLIC_`이 맞는 자리다.
- **REST 키는 건드리지 않았다.** `KAKAO_REST_API_KEY`는 서버 전용이고 `NEXT_PUBLIC_`을
  붙이면 안 되는 키다. 이름이 비슷해 섞이기 쉬워 example에 둘의 차이를 명시했다.
- **기존 `KAKAO_JS_KEY`는 지우지 않았다.** 읽는 코드가 없지만, 다른 작업자가 의도해서 넣었을
  수 있고 지우는 쪽이 되돌리기 어렵다.

## 사고 이력 — 같은 자리를 만질 사람에게

`vercel env pull`은 sensitive로 표시된 변수의 값을 **마스킹해서 내려준다.** 그 값을 그대로
다른 변수에 넣으면 마스킹 문자열이 저장된다. 이번에 실제로 그렇게 넣었다가, 서로 다른
변수 여러 개의 값 길이가 11자로 똑같은 것을 보고 발견해 삭제하고 실제 키로 다시 넣었다.
빌드는 그 사이에 돌지 않아 마스킹 값이 배포된 적은 없다. `env pull` 값을 신뢰하기 전에
길이나 형식을 먼저 확인할 것.

## 검증

- `pnpm check:prod https://ultspot.vercel.app` — **297건 통과 · 3건 skip · 0건 실패**
  (390/768/1440 전부). skip 3건은 클라우드 키가 없는 `cloud-storage.spec.ts`.
- 프로덕션에서 `https://dapi.kakao.com/v2/maps/sdk.js` 요청과 지도 타일 요청이 실제로
  나가는 것을 확인하고, 일정 화면의 지도를 스크린샷으로 직접 열어 확인했다 —
  서울시청–명동 구간에 `1. 하이커 그라운드`, `2. 뮤직코리아` 두 핀이 라벨과 함께 찍힌다.

## 하지 않은 것 · 미검증

- **카카오 콘솔 허용 도메인 설정** — 지도가 뜨는 것으로 `ultspot.vercel.app`이 통과한다는
  사실은 확인됐지만 콘솔 화면 자체는 보지 않았다. 다른 도메인이 필요하면 별도 작업이다.
- **Preview 환경의 지도** — 프로덕션에만 추가했다. Preview 배포에서는 여전히 지도가 없다.
- **Supabase 운영 DB 반영·RLS·실제 클라우드 저장/복원** — 키가 없어 여전히 미검증이다.
