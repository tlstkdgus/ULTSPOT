## 배경

사용자가 `202609200002_on_site_records.sql`을 운영 Supabase에 적용했다. 테이블 4개가 생기고
`anon`은 전부 401로 차단됐다. 익명 사용자 두 명으로 19건을 돌려보니 포인트 지급·중복 방지·
A/B 격리·포인트 위조 방어는 전부 의도대로였다.

**그런데 PGlite 테스트 12건이 전부 통과하던 SQL에서 두 가지가 드러났다.** 둘 다 운영에 올려
실제 데이터로 불러보지 않았으면 몰랐을 것이다.

## 결함 1 — 생일카페에서는 현황을 아예 쓸 수 없었다

`reviewed_place_id` 도메인이 `^[a-z0-9]+(-[a-z0-9]+)*$`, **소문자만** 허용했다.

| id | 결과 |
|---|---|
| `hikr-ground` | 통과 |
| `BC-SEUNGMIN-AUTUMN-BREAK` | **400 거부** |
| `BC-SEUNGMIN-DANDY-BOY` | **400 거부** |
| `BC-KYUNGMIN-CURIOUS-ANGEL` | **400 거부** |

검증된 상설 장소 3곳이 전부 소문자라 제약이 맞아 보였는데, PR #48로 들어온 팬 생일카페
id는 전부 대문자다. **대기 줄과 특전 잔여가 가장 중요한 곳이 정확히 생일카페인데 거기서만
막혀 있었다.**

원본 테스트가 `'HiKR-Ground'`를 거부 목록에 넣어 이 동작을 "계약"으로 고정해 두기까지 했다.
그러나 실제로 지키려던 것은 `personal-`/`custom-` 차단이다 — 그 id는 한 브라우저에만 있어서
공유 기록을 만들면 구성원이 한 명뿐이고 그 사용자의 목록이 새어 나간다. 대문자 금지는
곁다리였다.

**고친 방법**: 도메인을 `^[A-Za-z0-9]+(-[A-Za-z0-9]+)*$`로 넓히고, 개인 장소 차단은
`lower(value) not like ...`로 바꿔 `PERSONAL-x` 같은 대문자 우회를 막았다.

## 결함 2 — 내가 올린 현황을 내가 못 봤다

`place_status_summary`의 해금 조건이 **체크인 또는 30점 해제**뿐이었다. 현황 공유는 없었다.

```
A가 hikr-ground에 현황 공유 (+20점) → open_to_me: false, reports: 0
```

체크인은 `manual`이라 검증이 없다 — 버튼 한 번에 +10점과 무료 해금이다. 반면 현황 공유는
**현장에 서 있어야 알 수 있는 값**이고 +20점짜리다. 더 싼 기여는 열어주고 더 비싼 기여는
안 열어주는 셈이었고, 화면에서는 점수만 오르고 아무 변화가 없어 보인다.

**고친 방법**: 해금 조건에 "내가 그 장소에 현황을 올렸으면"을 추가했다. 아무 연결도 없는
장소는 여전히 닫혀 있어, 남의 기록을 공짜로 보는 길이 열리지는 않는다.

## 결정

- **테이블을 다시 만들지 않는다.** 이미 운영에 데이터가 생길 수 있어 `alter domain`과
  `create or replace function`으로만 바꾼다. 삭제·초기화 없음.
- **도메인 제약 이름을 조회해서 지운다.** 원본이 `create domain ... check (...)`로 이름 없이
  만들어 자동 이름이 붙었다. 이름을 박아두면 다른 환경에서 안 지워질 수 있다.
- **UI가 원인을 말하게 했다.** 도메인 거부를 `notShareable`로 분류해 "이 장소는 이 브라우저에만
  있어서 함께 볼 현황이 없어요"를 4개 언어로 띄운다. 이전에는 "처리하지 못했어요"뿐이었다.

## 하지 않은 것

- **카탈로그 id를 소문자로 바꾸기** — 이미 기기에 저장된 여정·일정의 `placeId`와 어긋나
  복원 시 장소를 잃는다. 이미지 매핑·번역 초안 키도 같이 깨진다.
- **체크인에 위치 검증 붙이기** — 판정 반경의 근거가 문서에 없다. 명세 §6이 "반경은 DB에
  넣지 않았다"고 한 것과 같은 이유다.
- **운영 DB에 이 마이그레이션 적용** — SQL Editor 접근 권한이 없다. 사용자가 실행해야 한다.

## 검증

- 데이터 테스트 **64건 통과 · 0 실패** (신규 2건). 새 마이그레이션을 원본과 함께 PGlite에 적용해
  대문자 id 허용·`PERSONAL-` 우회 차단·공백/언더스코어 여전히 거부·현황 공유로 해금을 고정했다.
- E2E **312건 통과 · 3건 skip · 0건 실패** (390/768/1440 전부)
- typecheck 0, lint 오류 0

### 아직 검증하지 못한 것

이 마이그레이션을 **운영에 적용한 뒤의 동작**. PGlite에서 통과한 것이 운영에서 통과한다는
보장이 아니라는 게 이번 태스크의 교훈이다. 적용 후 같은 19건을 다시 돌려 확인해야 한다.
