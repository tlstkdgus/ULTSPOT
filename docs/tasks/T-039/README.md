## 배경

T-029 통합(T-038)을 검증하려고 `main`에서 기준선을 재려다 **main이 이미 빨간 상태**임을
확인했다. `origin/main`(15ab7c9)에서 같은 스펙을 돌려 E2E 33건 실패, 데이터 2건 실패다.
통합 브랜치의 실패 31건은 그 부분집합이었다 — 병합이 만든 실패는 0건이다.

이대로 두면 T-029 통합이 무엇을 깨뜨렸는지 판별할 수 없고, 제출 전 검증이 아무것도
보증하지 못한다. 그래서 통합과 분리해 이 커밋에서 복구한다.

## 원인 세 가지

1. **PR #48이 카탈로그 앞에 생일카페 3건을 붙였다.** 스펙이 `catalog[0]`·`catalog[1]`·
   정렬 순서를 박아두고 있어서 `catalog[0]`이 `hikr-ground`(운영시간 600–1200, 월 휴무)에서
   `BC-SEUNGMIN-AUTUMN-BREAK`(opens `null`)로 바뀌자, 그것을 토대로 만든 편성·휴무·예약
   사례가 전부 다른 것을 검사하게 됐다. 실패 대부분이 여기서 나왔다.
2. **오늘이 2026-09-21이 됐다.** 두 검사가 오늘 날짜를 상수로 쓰고 있었다.
   - `locale.spec.ts`: 여행 날짜 입력의 기본값이 오늘이라 `fill("2026-09-21")`이 같은 값을
     넣어 change가 일어나지 않고 `changeDate()`가 돌지 않았다. 월요일 휴무 안내가 뜰 수 없다.
   - `on-site-records.test.mjs`: DB의 `current_date`(세션 시간대)를 러너의 UTC 날짜와 비교했다.
     KST는 UTC+9라 00:00–09:00 사이에는 하루가 어긋난다. 하루 중 9시간 동안 깨지는 검사였다.
3. **UI가 실제로 달라졌는데 검사가 옛 화면을 본다.** PR #48이 6곳 전부에 이미지를 붙여
   "사진 준비 중" 자리표시자가 카탈로그에서 사라졌고, T-036이 요약 타일을 넣어 "1곳 방문"이
   두 군데에 나오면서 strict mode 위반이 났다.

## 결정

- **인덱스 대신 id로 집는다.** `const spot = (id) => catalog.find(e => e.id === id)!`를 네
  스펙에 넣었다. 카탈로그는 앞으로도 늘어난다 — 순서에 기대는 검사는 데이터가 들어올 때마다
  다시 깨진다. 이번이 T-034 번호 충돌에 이은 같은 종류의 재발이다.
- **사라진 자리표시자를 되살리지 않았다.** 이미지가 붙은 것은 의도된 개선이다. 대신 실제
  사진이 렌더되는지를 본다. 자리표시자 자체는 개인 행사 경로에 그대로 남아 있다.
- **제외 목록은 순서가 아니라 사유로 확인한다.** `omitted[0]`은 카탈로그 순서를 따라가므로
  데이터가 늘면 또 바뀐다.
- **없는 번역을 만들지 않았다.** 생일카페 3건에 ja/zh 초안이 없어 `localization.test.mjs`가
  `undefined.translation_review`로 죽었다. 초안이 없는 것은 정상이고 계약(ja/zh는 영어로
  fallback, 카탈로그 행에 번역 필드가 실리지 않음)은 그대로 검사한다. 초안이 있을 때만
  status를 본다.

## 하지 않은 것

- **생일카페 3건의 ja/zh 번역 작성** — 검수하지 않은 기계 번역을 제출 직전에 넣지 않는다.
- **카탈로그 정렬 변경** — 스펙을 고치는 것이 맞지, 검사를 통과시키려고 데이터 순서를
  되돌리지 않는다.
- **`.github/skills/` 벤더 JS의 lint 경고 94건** — 이 작업과 무관한 반입 파일이다.
