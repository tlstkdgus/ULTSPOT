## 목표

여러 그룹·멤버·유닛·솔로의 실제 행사와 장소를 같은 기준으로 납품하고, 개발팀이 검수·임포트·검색·일정 확장 범위를 알 수 있게 한다.

## 진행 내역

수집 요청서·복사용 프롬프트·제품 반영 계획을 작성했다. PRD·기능명세·유저플로우·기획안·기존 수집 조사·현재 구현 계약·README에 새 기준을 연결했다.

## 결정

- 특정 그룹 한정은 초기 조사 사례이며 제품 제한이 아니다.
- 인물과 그룹·유닛, 장소와 행사, 사실과 추정, 수집과 공개 승인을 분리한다.
- 아티스트 선택 OR 및 관계 확장 규칙을 명시하고 개별 참석 보장과 구분한다.
- 공개 원문과 키 보유만으로 저장·재게시·AI 처리 권한을 추정하지 않는다.

## 하지 않은 것

UI·런타임·DB·환경 변수 수정, 실제 데이터 반입, 외부 수집팀 연락, 플랫폼별 새 법률 검토. 기존 FanEvent와 확장 명세의 차이를 후속 구현으로 남겼다.

## 검증

신규 문서 4개 내부 링크 5개 통과. pnpm lint, pnpm typecheck, git diff --check 완료(오류 0건). UI 변경 0건으로 캡처·E2E는 수행하지 않았다.

## 후속 작업

데이터 모델·임포트 검증·승인 도구 → 아티스트 검색/관계/필터 → 카탈로그 연결 → 시간 구간 엔진 확장 → 운영 갱신·교통·AI 검증. 수집 담당자는 아티스트 범위·여행 기간·납품 기한을 채워 프롬프트를 사용한다.
