## 배경

공지 보고 행사 추가는 이름·주소를 손으로 적는 폼이라 **좌표가 없었다.** 그래서 직접 추가한 곳은

- 이동시간이 늘 "미확인 · 계획용 여유 45분"이었고,
- 지도에 핀이 없었고,
- 그곳 기준의 주변 추천·빈 시간 채우기 기준점이 될 수 없었다.

주변 추천 패널의 "내 장소에 담기"도 좌표를 버리고 주소 글자만 넘겼다.

## 결정

- 폼 위에 **지도에서 장소 찾기(선택)**. 카카오 로컬 키워드 검색 상위 8건을 서버(`/api/place-search`)로 받는다(REST 키는 서버).
  고르면 행사 이름(비어 있을 때만)·동네(주소의 구)·주소가 채워지고 좌표가 붙는다. 검색은 선택이다.
- 검색창은 폼 **밖**에 둔다. 안에 두면 Enter가 행사 추가 폼을 제출한다.
- 저장본 규칙: `coord`는 검수 전용 필드라 개인 저장본에서 거부했다. **출처가 카카오 장소 페이지(`https://place.map.kakao.com/<id>`)인
  한국 좌표만** 개인 행사·직접 추가 장소에 허용한다. 그 밖의 좌표(검수 카탈로그 출처, 손으로 만든 값)는 여전히 거부한다.
- 주변 추천의 카카오 후보를 담을 때도 좌표를 유지한다(출처 = 그 후보의 카카오 장소 페이지). 관광공사 후보는 출처 규칙에 맞지 않아 좌표 없이 담긴다.
- 서울 시청을 기준점으로 넘겨 같은 이름이면 서울 쪽이 앞에 온다. 반경은 두지 않는다(공항 숙소 등).
- 서버: IP당 분당 20회, 하루 500회(`PLACE_SEARCH_DAILY_BUDGET`), 같은 검색어 30분 캐시, 실패는 캐시하지 않음.
- 개인정보 처리방침에 "검색어가 서버를 거쳐 카카오 장소 검색에 전달된다"를 4개 언어로 추가했다.

## 하지 않은 것

- 검색 결과를 지도에 핀으로 보여주기. 목록으로 충분하고, 카카오 검색 결과를 Google 지도에 올리는 문제를 만들지 않는다.
- 여러 날 여정의 "장소 직접 추가" 화면. **문구만 있고 화면에 폼이 없었다**(이번에 확인). 저장 형식은 검색 좌표를 받도록 넓혔다.
- 관광공사 후보 좌표 유지. 출처 규칙을 넓혀야 한다.

## 검증

- 신규 `e2e/place-search.spec.ts`: 키워드 응답 해석(한국 밖·ID 없음 제외, 구 추출), 저장본 좌표 규칙(검색 출처만 허용),
  라우트 입력 검사(400·413), 화면 — 검색 → 선택 → 이름·동네·주소 채움 → 추가·담기 → **모든 구간이 조회된 이동시간**.
