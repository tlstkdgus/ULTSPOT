## 배경

Kiro가 만든 체크인·가계부·발자취(PR #50)가 `feat/T-029-full-ux`에 있었다. 이 브랜치의
공통 조상은 `30020cf`로, 그 뒤 main이 41 커밋 앞서갔다(PR #47 여정 통합, #49 카카오 지도·
T-036 조판, #48 생일카페 카탈로그). GitHub은 CONFLICTING을 보고했다.

## 결정

- **main을 기준으로 잡고 기능 브랜치를 끌어왔다.** 반대 방향으로 합치면 T-029의 낡은 기준
  파일이 main의 지도·조판 작업을 덮을 위험이 있다. 충돌은 `docs/` 2건뿐이었고 소스는 전부
  자동 병합됐다 — Kiro가 파일 소유권을 지킨 덕이다.
- **`docs/tasks/T-035/`는 main 쪽을 남겼다.** 번호가 겹쳤다. main의 T-035는 "Kiro 여정·현장
  기록 통합", 기능 브랜치의 T-035는 "이전 이동시간 조회 취소"다. 후자의 코드는 이 병합으로
  들어오고, 그 기록은 아래 "함께 들어온 것"에 남긴다. 번호 충돌은 이번이 T-034에 이어 두
  번째다 — `docs/tasks/README.md` 마지막 번호만 보면 남의 브랜치를 못 본다.
- **`docs/tasks/README.md` 머리말은 main 쪽을 남겼다.** main에서 표 머리글이 문서 중간으로
  밀려난 상태인데, 이 PR에서 되돌리면 병합 diff에 기능과 무관한 문서 재배치가 섞인다.

## 함께 들어온 것 (구 T-035)

여정 변경 중 두 방문을 다른 날짜로 나누면 조회 구간이 0개가 된다. 기존 코드는 이때 요청
번호와 조회 중 상태를 갱신하지 않아 늦게 온 응답이 적용되거나 "조회 중" 표시가 남았다.
빈 구간도 이전 요청을 무효화하고, effect cleanup의 `AbortController`로 요청을 취소한다.

## 하지 않은 것

- **자동 저장·자동 복원** — 현장 기록도 기존 기기 저장/복원 버튼을 쓴다. Codex가 records-ui
  테스트를 이 계약에 맞췄다. 자동 저장은 별도 동작 변경과 오류 안내가 필요하다.
- **여정 화면 비주얼 손대기** — 이번엔 통합만 했다.
- **Supabase 운영 DB 적용** — 마이그레이션 파일 존재와 운영 반영은 별개다. 현장 기록은
  기기 저장으로 동작하며 이 PR은 운영 DB를 건드리지 않는다.
- **팬 생일카페 3건의 ja/zh 번역** — 없는 번역을 지어내지 않는다. 영어 fallback이 걸린다.
