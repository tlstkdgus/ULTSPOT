# 지도·Jev 통합 전 검토 (T-024)

2026-09-20. Kiro checkout HEAD d188e36의 경로 코드 기준. 수집 스크립트와 package.json은 병렬 수정 중이라 변경하지 않았다. 검토 이후 수정 여부는 검사 출력의 sourceHashes로 구분한다.

## 현재 연결 상태

- 카카오 교체 키: 루트에서 도보·대중교통 실제 HTTP 200 확인. Jev는 PR #28에서 합성 30건 평가 완료. 키 값은 문서·검사에 포함하지 않는다.
- `src/components/trip-planner.tsx`의 generate와 저장 복원은 `planTrip(events, input)`만 호출한다. `fetchTravelTable` 호출과 travel 인자 전달은 아직 없다. API 모듈 존재만으로 실제 화면 연결 완료가 아니다.
- 현재 checkout의 src에 Jev/TypeSafe 어댑터는 없다. PR #28의 평가 계약을 먼저 확인한다.

## 먼저 수정할 문제

| 우선순위 | 위치 | 재현 | 수정 완료 기준 |
|---|---|---|---|
| 높음 | api/travel/route.ts pending | 같은 구간 42개 → 외부 호출 42회, 응답 1개 | 좌표·방향·수단 기준 고유 요청 1회, 여러 ID라면 응답 키별 연결 유지. 예산도 고유 호출 기준 |
| 높음 | route.ts → kakao.ts | fetch에 AbortSignal 없음 | 요청 취소와 서버 deadline 전달, 무응답 시 제한 시간 내 unconfirmed. 신호 존재 검사 외 무응답 테스트 필요 |
| 높음 | route.ts readPoint/legs | 같은 ID, 다른 좌표 2개 → 200 및 외부 호출 2회 | 충돌 ID는 조회 전 400. 구간 키 구분자 충돌도 검토 |
| 중간 | route.ts request.text | 40,084바이트 / 14,884문자 요청 → 200 | 16,384바이트 초과 413. Content-Length 없이도 스트림 읽기 중 제한 |

메모리의 일일 예산은 인스턴스별이므로 서비스 전체 요금 상한이 아니다. 공개 배포 전에 공용 예산 저장소 또는 공급자 측 실제 호출 차단 설정을 확인한다. 무료 초과 청구를 켜는 것으로 해결하지 않는다.

## 수정 후 실행

T-024 브랜치에서, 의존성이 설치된 상태로:

```sh
node scripts/review/travel-contract.mjs ../ULTSPOT-kiro
```

인자는 검사 대상 checkout 절대 경로도 가능하다. 신뢰하는 프로젝트 코드만 대상으로 한다. TypeScript를 메모리에서 변환하고 fetch와 env를 가짜 값으로 주입한다. 대상 파일·실제 env는 쓰지 않는다. 네트워크 호출 0회. 불일치가 있으면 종료 코드 1이며, 현재 결과는 4 통과 / 4 실패다. 이 스크립트는 해당 모듈 구조에 한정한 검사로, 구조 변경 시 import 허용 목록을 검토해야 한다.

## 화면까지 통합 완료 기준

1. generate: 유효 후보만 정리 → planningLegs → fetchTravelTable → planTrip에 조회 결과 전달. 날짜·선택·이동수단 변경이나 재생성 시 이전 응답이 최신 결과를 덮지 않도록 취소와 요청 ID를 처리한다.
2. 저장 복원: 과거 경로를 최신 조회값으로 표시하지 않는다. 새 조회를 하거나 조회 시각·미확인 상태를 명시한다. 실패 시 재시도와 직접 지도 확인 경로를 제공한다.
3. 경로 검증: 계획용 buffer를 확인된 이동시간으로 바꾸지 않는다. 행사 시간·예약·입장 마감·식당 휴무를 먼저 검사한다. 날짜/출발 시각을 전송하지 않는 현재 조회를 미래 시간대 보장으로 표현하지 않는다.
4. Jev: 검수된 후보의 취향 순위만 판단. 실제 사용자 데이터 전송 범위를 정하고 서버 전용 키·timeout·응답 검증·기능 플래그·기본 추천 복귀를 구현한다. 사실/가격/운영시간/좌표를 생성하지 않는다.
5. 실제 행사 1곳 + 주변 식당 2곳을 검수한 뒤 한국어·영어에서 일정 생성→저장→새로고침 복원. API 실패·좌표 누락·조회 중 조건 변경도 브라우저에서 검사한다.
6. Claude 최신 다국어 UI와 합친 뒤 3개 뷰포트 캡처. 서버 키가 클라이언트 번들/응답에 없는지 확인. 프로덕션 환경 변수는 로컬 설정과 별도로 확인한다.

이 문서는 Kiro에게 자동 전달된 메시지가 아니다. Codex는 검토 도구와 기준을 제공하며, Kiro의 구현 브랜치는 수정하지 않았다.
