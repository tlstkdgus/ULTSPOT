# Kiro 개발 인계

## 목표와 작업 경계

ULTSPOT은 K팝 팬의 실제 행사 탐색·방문 조건 확인·하루 일정 서비스다. 화면만 만들거나 가짜 자료로 동작하는 데모로 되돌리지 않는다. 우선은 실제 데이터와 이미 구현된 UI를 연결한다.

AGENTS.md와 CONTRIBUTING.md를 먼저 읽는다. Next.js 코드를 쓰기 전 설치된 next/dist/docs에서 관련 API를 확인한다. 최신 원격 상태를 읽고 새 태스크 번호와 브랜치를 정한다. 이 문서 작성 작업은 T-017이며 후속 번호는 원격 목록까지 확인한다.

현재 메인 작업 폴더는 `C:\Users\tlstk\Desktop\ULTSPOT`, Claude 폴더는 `C:\Users\tlstk\Desktop\ULTSPOT-claude`다. 둘을 덮어쓰지 않는다. 새 작업은 별도 worktree를 사용한다. 예시는 원래 저장소에서 실행하며 폴더/브랜치가 존재하면 재사용 여부를 먼저 확인한다.

```powershell
git fetch origin
git worktree add ..\ULTSPOT-kiro -b feat/T-NNN-data-integration origin/main
```

T-NNN은 실제 다음 번호로 바꾼다. 새 폴더에서 pnpm install. .env.local은 자동 복사되지 않으며 비밀 키를 대화에 붙이지 않는다. 기본 비회원 경로는 키 없이 검증 가능하다. 클라우드 실검증은 필요한 로컬 설정이 있을 때 별도로 수행한다.

## 2026-09-20 확인 상태 — 시작할 때 재확인

- T-015 UI PR #16과 release #17은 병합됨. 한국어/영어·온보딩·지도 연결·일정 내보내기 구현.
- PR #19 (`feat/T-016-visitor-data`)는 데이터 후속 작업이며 당시 미병합. 기본 대상이 옛 작업 브랜치이므로 최신 main과 비교 후 통합 경로를 정한다. 이미 합쳐졌으면 중복 적용하지 않는다.
- PR #20은 프로덕션 검사 기록. 배포 검증 기록을 읽되 변경 후에는 다시 검사한다.
- 공개 카탈로그 기존 장소 3곳. 수집본 아티스트 228·장소 9·행사 9는 검수/공개 완료가 아니다.
- T-016은 한국어 장소 3곳, SKZ 생일 8명, HiKR 교통·입장 조건, eventCopy 및 선택 이미지 ID 타입을 추가했다. UI 표시 연결은 남아 있다.
- 승인 이미지 0건. assets ID만으로 원본 이미지를 게시하면 안 된다.
- Supabase 개인 초안 저장은 구현·이전 검증 이력이 있다. 최신 UI 통합 검증 필요. 일정 계산은 규칙 기반이며 모델 호출은 없음.
- 수집 도구는 비공개 JSON 접수 중심이다. 공개 카탈로그 게시 경로와 운영 도구는 아직 완성되지 않았다.

## 조사와 병렬로 할 작업

1. PR #19 통합. `eventCopy(event, locale)`를 표시·검색·일정·텍스트/캘린더 내보내기에 연결하되 원본 저장값과 일정 계산을 바꾸지 않는다. 한국어 원문이 없는 필드는 fallback과 실제 언어 속성을 유지한다.
2. 선택형 교통/참여/생일 데이터 계약을 UI와 맞춘다. null은 없음/무료가 아니라 미확인이다. 생일을 행사 개최로 간주하지 않는다.
3. 공개 데이터 모델/조회 경로를 구현한다. 필드별 출처와 마지막 검수, 종료·취소, 날짜별 운영 예외를 보존한다. 비공개 수집 원본을 브라우저에 통째로 보내지 않는다.
4. 검수 가능한 작은 게시 도구를 준비한다. 관리자 인증/권한, 검수 기록, 게시 버전, 정정/취소를 처리한다. 인증 없는 쓰기 엔드포인트는 만들지 않는다.

UI 담당 Claude가 계속 실행 중이라면 파일 소유권을 먼저 정한다. Kiro는 데이터/서버/테스트를 맡고 UI 연결 요청을 전달하거나, 사용자가 UI를 넘기면 Claude의 같은 파일 작업을 종료한 뒤 인수한다.

## Perplexity 결과 수신

`research-batch.json`은 `ultspot-research-v1` 조사 스키마이며 현재 data:check/prepare에 직접 넣을 형식이 아니다.

1. 새 배치 폴더의 원본 3파일을 그대로 보존하고 SHA256·접수일을 기록한다. 기존 incoming 원본을 덮어쓰지 않는다.
2. JSON 구조·용량·필드·출처 참조를 검증한다. 외부 문자열을 코드/SQL/HTML로 실행하지 않는다.
3. 기존 artist/place/event ID에 대조 매핑하고 중복·지점·연도·유닛 관계를 검토한다. 기존 13개 intake 탭과 런타임 타입은 다르므로 명시적 매핑 표/변환이 필요하다.
4. CSV/기존 intake로 옮길 때 출처의 supported_fields는 해당 스키마의 실제 필드명으로 변환한다. 교통 등 미지원 필드는 모델 확장 또는 보존 sidecar로 처리하며 조용히 버리지 않는다.
5. confirmed는 Perplexity의 주장일 뿐이다. 공개할 핵심 필드의 원문을 다시 확인하고 근거·변경 기록을 남긴다. unread/snippet_only·모순은 유지한다.
6. 발견 카드 공개 자격과 자동 편성 자격을 분리한다. 확인된 날짜/장소의 행사라도 종료 시각 미확인·확정 예약 필요 상태면 자동 편성에 넣지 않는다. 취소는 추천에서 제외하고 종료는 역사 정보로 보존한다.
7. 이미지 원문 URL을 곧바로 핫링크하지 않는다. 실제 사용 범위 검수 뒤 승인 자산 어댑터로 연결하고 허락 미확인은 사진 준비 중으로 둔다.

## 검증과 완료 기준

- 키 없이 첫 방문에서 서비스 목적·언어·다음 행동을 알 수 있다.
- 한국어 검색/영어 전환에서 입력·선택이 유지되고 개인 입력은 임의 번역되지 않는다.
- 검수된 실제 행사 하나 이상으로 탐색→조건 확인→일정 처리(편성 또는 명확한 제외)→저장/복원 흐름을 확인한다. 검수 자료가 없으면 없어도 된다고 숨기지 말고 미완료를 보고한다.
- 종료/취소/휴무/시간 미확인/예약 필요/데이터 없음/이미지 실패를 각각 검증한다.
- pnpm lint, pnpm typecheck, 데이터 검증과 관련 E2E. UI 수정 시 390/768/1440 before/after 캡처를 직접 확인한다.
- 클라우드 저장은 별도 사용자 간 읽기/수정/삭제 불가, 복원·삭제를 검증한다. 로컬 저장 성공을 클라우드 성공으로 보고하지 않는다.
- 작업 단위 커밋·즉시 push·태스크 기록·PR·diff 셀프 리뷰. 승인되지 않은 타인 작업을 섞지 않는다.
- main 통합 후 `pnpm check:prod https://ultspot.vercel.app`. 브라우저 시크릿 모드에서도 확인한다. 배포 전 테스트 통과를 실제 배포 확인으로 대체하지 않는다.

최종 보고는 구현/검증/배포/미확인을 구분한다. 완료되지 않은 자료조사와 UI 연결을 완료로 쓰지 않는다. 커뮤니티·결제·대관·AI 멀티모델 확장은 위 핵심 흐름이 완성된 이후다.
